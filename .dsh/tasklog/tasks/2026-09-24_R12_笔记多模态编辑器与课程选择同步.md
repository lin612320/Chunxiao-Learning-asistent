# 2026-09-24 R12 修「建课后课程选择不更新」+ 笔记沉浸式多模态编辑器（文本 / 图片 / 公式）

- **目标（用户原话，两条）**：①「创建课程后主页左上角顶部的课程选择没有跟着更新」；②「笔记需要支持多模态，最好是点笔记有一个单独文件窗口，这个文件窗口支持文本输入、粘贴图片等，还要有简单的格式渲染（比如代码块、字体大小、主副标题、公式等）这些你可以参考一些别的学习笔记软件」。
- **结果**：两条都完成、通过验证，并**已发版出包 0.9.0**（构建日期 2026-09-27）。
- **三个设计岔路（用户当场拍板）**：① 应用内**沉浸式编辑页**（不是真正的独立 OS 窗口）；② **内置 KaTeX**（不是手写轻量渲染器、也不是不做）；③ 图片**内联 dataURL 进正文**（不是存本地文件 + 路径）。
- **缺陷 ① 的根因**：`hooks/useCourses.ts` 是内部持 `useState` 的普通 hook → **10 个调用方各拿一份独立副本**，各自 mount 时拉一次；侧栏选择器/顶栏胶囊是**常驻组件**（路由切换不重挂载），只有发起写入的课程列表页那一份会 `refresh()` → 新课**到整页刷新前都不出现**。
  - 处置：改**模块级单一存储 + `useSyncExternalStore`**（写入即广播；启动 IPC 10 次 → 1 次）。
  - **这是 R9 同一类错误的第二次**：R9 只修了"读 URL"那一半，没修"数据来源"那一半（`docs/20` §2 的结论"把唯一事实来源写进契约 ≠ 它真的唯一"）。
  - 单例化后新出现的两个坑，都修了：① `callRust` 失败返回 `null`，不能再当成空数组（否则**一次瞬时失败抹掉全应用的列表**）→ 改成"取到数组才替换"；② 在途的旧读取会盖掉刚写完的数据 → `refreshCourses(force)` + 请求序号 `seq`，**迟到的旧请求直接丢弃**。
  - 第二层：`Courses.tsx` 原来只 `nav('/course/' + id)`，**不带 `?course=`、不记 last-course** → 新课不会被选上。改成与侧栏切课**同一套口径**（`rememberLastCourseId` + `?course=`）。
- **需求 ② 的产出**：
  - 路由 `/note/:id`（`App.tsx`）；`components/Layout.tsx` 新增**第三种外壳** `editor-shell`（不渲染侧栏与顶栏）。
  - `src/views/NoteEditor.tsx`（新增） + `src/views/NoteEditor.css`（新增）。
  - 能力：Markdown 源码输入 + 实时预览（编辑/分栏/预览三档）、H1–H6、加粗斜体行内代码、代码块、引用、有序/无序列表、链接、表格、分隔线；**图片三入口**（`Ctrl+V` / 拖入 / 选文件）复用 R4 的 `lib/images.ts`（压 1600px 长边、单条 3 MB、**超限逐条如实说明**）；`Ctrl+S/B/I`、Tab 缩进、**回车续列表**、未保存拦截离开、字数与保存状态。
  - 笔记列表：条目主按钮改为**打开编辑页**，旁边保留「阅读」按钮走原来的本页预览（批注/导出那条路没丢）。
  - `components/Icon.tsx` 新增 12 个**手绘**工具栏图标（零依赖惯例不变）。
- **⚠ 依赖登记（必须记住）**：引入 **`katex@0.16.11`** —— **本项目历史上第一个第三方前端依赖**，直接冲突于 `Icon.tsx` 里写着的「项目硬约定『不新增第三方依赖』」与 `markdown.tsx` 的"零依赖手写渲染器"自居。代价已量化：主包 392 → **407 KB**、KaTeX 块 **260 KB**、CSS 86 → **118 KB**、字体 **60 个文件 ≈ 1.0 MB**（不能省，缺字形会显示成方块）、依赖树 `+2 packages`。
  - **为什么单独拆块**：并进主包会到 669 KB、**跨过 vite 的 500 KB 阈值**，每次构建都报 chunk 过大警告 —— 本项目历来把"构建 0 warning"当口径。拆块后 **0 warning**。
- **安全红线怎么守住的**：红线是「禁止 `dangerouslySetInnerHTML`、禁止拼 HTML 字符串」，而 KaTeX 最常用的 `renderToString()` 返回 HTML 字符串、只能 innerHTML 塞进去 —— **直接违规**。所以用**命令式** `katex.render(tex, el, { displayMode, throwOnError: false })`（直接建真实 DOM）。已 grep 确认两文件里 `dangerouslySetInnerHTML` **零出现**。KaTeX 无 `.d.ts` 且本轮不许再装东西 → 命名空间导入 + 就地收窄 + `@ts-expect-error` 精确抑制 TS7016（补上类型后该行会立刻报"未使用的 expect-error"，逼维护者删掉）。
- **本轮最值钱的发现（新断言第一次跑就红）**：断言「插入的图片在预览里真的渲染出来」首跑即 `[FAIL] … {"ok":true,"inText":true,"rendered":0}` —— `inText:true` 说明图片**确实写进了 `content_md`**，但预览里 `<img>` 是 0。查下来**两层叠加**：① `markdown.tsx` 的渲染器**从来没有图片规则**（`![alt](src)` 被拆成"`!` + 一个链接"）；② `safeHref()` 是**链接**白名单、**刻意**拒 `data:`。⇒ **"笔记支持粘贴图片"这个需求，光在前端插入 Markdown 是不成立的** —— 用户会得到一段看着像图片、实际什么都不显示的源码。
  - 处置：新增图片规则 + **图片专用窄白名单** `safeImageSrc()`：只放行 `data:image/{png,jpeg,jpg,webp,gif};base64,…` 与 `http(s):`，**刻意排除 `image/svg+xml`**（可执行文档类型；而图片管线只产得出 png/jpeg，排除它挡不住任何真实用法）；不安全地址整段降级为纯文本。
  - 偏移尺子保持一致：`<img>` 在 DOM 里不产生文本 → `plainInline()` 也让图片贡献 0 个字符（比公式那段干净）。
  - 与 `docs/22` §五.3（悬浮球抽屉叠字：8 层验证没一层会红）同一个道理：**覆盖"我以为该看的地方" ≠ 覆盖用户会碰到的地方**。
- **已知局限（如实登记，不做假实现）**：
  - **含行内公式的块不再支持新建批注**：KaTeX 在 DOM 里产生真字符 → `textContent` 与 `blockPlainTexts()` 不再逐字相等（批注偏移尺子）。本次选择"尺子优先"（公式按**原文长度**参与偏移），并在 `Notes.tsx` 里**拒绝在含公式的块上新建批注并说明原因**；已有批注仍按原文片段自动校验与修正，找不回的照旧进「已失效的批注」。**根治需要 Shadow DOM 渲染公式**，本轮未做。渲染器导出 `hasInlineMath()` / `blockHasInlineMath()` 供调用方探测。
  - **行内公式不把 `\$` 当转义**：`\$5 and \$10` 不会被误判，但转义美元与真公式混排（`\$5 和 $x$`）时中间那段会被当成公式。加 `(?<!\\)` 的收益很窄（公式体本来就 `[^$\n]`、不许含 `$`），本轮不做。
  - **笔记保存链路无自动化**：浏览器预览下写入一律**如实抛**「仅桌面版可用」（既有契约，**没有**为便于测试而放宽）→ 冒烟断言的是"**如实报错**"而非"保存成功"；`note_update` → SQLite 需要桌面真机层覆盖，本轮未做。
