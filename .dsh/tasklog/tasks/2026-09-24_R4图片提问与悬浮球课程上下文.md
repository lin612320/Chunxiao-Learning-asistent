- **关键决策**：
  - **纠正了一个用户前提**：「无视觉模型时自动转录兜底」在纯本机条件下**不成立** —— 项目不做本地 OCR，"转录"本身也是把图发给视觉模型。于是实现成：**能看图就直接发图；否则用"单独指定的视觉模型"转写；都没有就如实报错**，并在设置页显示"现在会怎么走"。
  - **图片入库**（用户选"存图可回看"）：新增列而非新表；走 `ensure_column` 幂等迁移，旧库平滑升级；**大小双保险**（前端 3 MB 提示 / Rust 6 MB 硬上限，超限**整条拒绝**）。
  - **悬浮球问答落库放在 Rust**（而非原计划的"前端挂 `onBallPush`"）：球是独立应用，用户可能压根没开主程序界面 —— 桥接轮询线程直接写库，前端只负责刷新。比 `docs/11` §六 原方案更稳。
  - **课程上下文的单一事实来源在主程序**（`settings.ball.course_id`）：随 `show`/`prefill` 下发，球只显示与回写；**不自动套用"最近课程"**（守 `docs/11` §一 第 3 条）。

- **坑（5 个真问题，全都"不查就会带病发布"）**：
  1. **面板 CSP 拦掉 `data:` 图片**：`default-src 'self'` 之下缩略图必坏，且除控制台外无提示 → 补 `img-src 'self' data:`。
  2. **`BridgeMsg.text` 必填**会让不带文本的 `set_course` 反序列化失败、被轮询线程静默 `continue`（现象："球说已切换，主程序毫无反应"）→ 改可选并加单测锁住。
  3. **`chat_history_save` 是"先删后插"整表重写**：图片若在事务中途才判超限会留半截消息 → 改为先整体校验再进事务。
  4. **真机冒烟跑的是旧 exe**：只跑 `cargo check` 时 `target/debug/*.exe` 仍是旧二进制 → `images` 全 null、超限不报错，**看起来像功能没实现**。必须先 `cargo build`。
  5. **自检不该改变被测对象状态**：第一版把自检会话留在库里，污染了后面 R1 的会话列表断言（连带 3 条失败）→ 自检会话用完即删。
