# 2026-09-27 R13 侧栏「相关材料」+ 点材料直接打开原文件

- **目标（用户原话）**：「在侧栏添加一个相关材料，点击材料可以直接跳转窗口（比如 pdf 点开就打开 pdf）」。
- **结果**：完成并验证；**未发版**（版本仍 `0.9.0`，未递增、未重打悬浮球、未出安装包）。
- **⚠ 本轮最核心的发现：这件事在本项目里原本做不到。**
  材料的正文一直是按**字节**导入的（前端 `<input type=file>` 拿得到 `File`，**拿不到绝对路径**），
  所以 `views/Course.tsx` 里 `material_add` 的 `filePath` **一直硬编码成空字符串**
  （注释写着「字节导入没有真实路径（M1 契约 §4.1）」）。而 `open_file` 需要**真实存在的路径** ——
  于是 **`open_file` 这个 Rust 命令从 M0 建起来之后从来没有被前端调用过**，
  「点材料打开」根本无从谈起。**所以真正要做的是先让材料有原文件可开。**
- **产出**：
  - **Rust 新命令 `material_store_file(fileName, dataB64) -> String`**：把导入的原始文件在
    `%APPDATA%\com.chunxiao.study\materials\<原名主干>__<内容指纹8位>.<ext>` **留一份副本**并返回路径。
    指纹用零依赖 FNV-1a：**同内容复用同一份**、**同名不同内容不互相覆盖**（多课程都有「课件.pdf」是常态）。
  - **Rust 新命令 `material_set_path(id, filePath)`**：给**已有**材料补记路径，**只改 `file_path` 一列**。
  - `OK_EXT` 白名单**补 `pptx`**：应用本来就能导入 pptx，打开白名单却没有它（"导得进来、点开说不支持"）。
  - 导入字节的校验/解码抽成 `decode_import_bytes` / `safe_file_name` 供两条命令共用
    （重构后 `extract_material_b64` **行为与文案逐字未变**，既有单测仍过）。
  - **前端**：`Course.tsx` 的 `insertMaterial` 先留副本再入库（失败**不牵连整条导入**，退回空路径）；
    侧栏新增 **「相关材料」**（课程态 `?course=N` / 全部态分组）；**新页面 `views/Materials.tsx`** + 路由 `/materials`；
    `nav.ts` 补标题；`Icon.tsx` 补 `folder` / `external` 手绘图标；`fmtSize` 挪到 `lib/materials.ts` 共用。
- **诚实分支（本轮刻意做的产品决定）**：**你现有材料的 `file_path` 全是空的**（R13 之前都没有副本）。
  材料页对这些**不摆点了没反应的「打开」**，而是明说「只导入过内容，没有原文件位置」+
  给「**补存原文件**」：重选一次原文件 → 落副本 → 记路径 → 以后就能打开。
  为了让这条分支在冒烟里**走得到**，`data/sample.ts` 特意加了一条 `file_path: ""` 的示例材料。
- **验证（实测）**：`tsc --noEmit` exit 0 · `vite build` **exit 0 · 0 warning** · `cargo check` **error=0 warning=0** ·
  **Rust 单测 70/70**（67 → 70）· **浏览器层 UI 冒烟 132/132**（124 → 132，新增 8 条）。
  - 新增 3 条 Rust 单测：`material_store_helpers_sanitize_and_validate`（文件名清洗**不许变成路径** /
    指纹稳定 / 非法 base64 被拒）、`store_material_bytes_names_fingerprints_and_reuses`
    （**真的写盘**：临时目录里验命名、同内容复用、同名不同内容不覆盖）、
    `material_set_path_only_touches_file_path`（补路径不许动正文/切块/来源标注；不存在 id 报错）。
  - 新增 8 条浏览器断言：侧栏入口 / 进得去 / 不带参数按课程分组 / 锁定课程不串课 /
    有路径摆「打开」/ **无路径摆「补存原文件」而不是「打开」** / **无路径时如实写明原因** / 预览下点「打开」如实报错。
- **本轮发现并修掉的一条自己的坏断言**：「不带课程参数时按课程分组」原来依赖上一步的残留状态
  （R12 段落刚建了一门课并选中它 → 实际落到 `?course=<新课>`、分组数 0 → 红）。
  改成**自己显式导航到不带参数的模式**。又一次印证：**断言依赖别人留下的状态就会随机红**。
- **⚠ 未跑（如实登记）**：`scripts/smoke-desktop-ui.mjs` 新增 5 条真机断言（侧栏入口 / 材料页在真机下能开 /
  空库诚实态 / 两个新命令的**拒绝路径**），**本轮没有执行** —— 该脚本要求主程序**未在运行**
  （它要移开真实数据库），而跑的时候用户正开着春晓。这 5 条**挂在隔离自检通过之后**（「空库」前提）。
  因此这条**仍无自动化证据**：**「真机上导入一个文件 → 副本真的落盘 → 路径真的写进库」的端到端链路**
  （它需要一次真实导入、走系统文件选择框，CDP 里无法自动化）。它目前被拆成两半验证：
  落盘与命名由 Rust 单测覆盖、命令注册与参数名由编译期覆盖。
  补跑方式：**先关掉春晓**，再 `powershell -File scripts/smoke-desktop-ui.ps1`。
- **已知局限**：材料在本机**多占一份磁盘**（单文件上限 20 MB，是为"点开就能打开"付的代价）；
  **删材料不删 `materials/` 里的副本**（可能被别的材料共用），暂无"清理未引用素材"入口；
  **「在应用内预览 PDF」没做** —— 现在是把文件交给**系统默认程序**（PDF 用你的 PDF 阅读器）。
