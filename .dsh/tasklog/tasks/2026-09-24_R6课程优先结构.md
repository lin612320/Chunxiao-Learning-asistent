- **关键决策**：
  - **侧栏就是"这门课的功能列表"**，而不是把 4 个页面塞进课程页做内嵌标签：后者要给 4 个组件各加"内嵌模式"（标题/高度/双层 shell），改动面大且容易藏出"标题重复、高度算错"。现在语义一致（进了课，侧栏列的就是这门课的功能），风险小得多。
  - **`get_courses` 刻意不 spawn 主程序**：为了填一个下拉把整个应用启动起来，比下拉空着更糟。
  - **手动写笔记不走"先建空笔记再编辑"**：Rust 侧要求标题与正文都不为空（诚实口径），所以先写、写好了再入库。
- **本轮最该记住的（第 5 条的方法论）**：用户说"对话窗口太小"，实测发现**窗口没问题，是输入区占了 278px、把消息区挤到 190px**。**先量再改**：`.content` 内边距 88px、两行控制项 + 一句与 `title` 重复的说明、`rows=3` —— 三处叠加。改完 **190 → 292px（+54%）**。
- **验证（实测）**：闸门 **9/9**（第 7/8/9 步真跑）· Rust **65/65** · UI 冒烟 **92/92** · 桌面真机 **18/18** · 悬浮球版面守门 **42/42** · **`get_courses` 端到端**（写桥接文件 → 0.98 秒收到课程列表）· 对话消息区 **190 → 292px**。
- **踩到的坑**：
  1. **调试版 exe 不是最新的**：`cargo check` 不产出 exe，所以第一次做 `get_courses` 端到端验证时用的是旧二进制 → 表现为"链没通"，重新 `cargo build` 后才通。**真机验证前必须 `cargo build`**（与 R4 记过的同一条坑）。
  2. **改结构必然打断冒烟断言**：删掉对话页「在聊哪门课」选择器后，真机冒烟的"从界面读到一门真实课程"读到空数组 → **三条断言连带失败**。处置是把断言口径跟着产品改成读**侧栏选择器**，而不是把选择器加回去。
  3. **截图工具的坑**：Windows 下无头窗口有最小宽度（约 500px），`--window-size=420` 不生效（页面按 492 排版、截图只截左边 420）→ 误判成"面板右侧被裁"。**要按精确 CSS 像素排版必须走 CDP 的 `Emulation.setDeviceMetricsOverride`**。
