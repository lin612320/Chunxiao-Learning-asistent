- **关键决策**：
  - **球的检索范围"跟随"而不是"猜"**：`docs/11` §一 第 3 条禁止的是**自动套用"最近使用的课程"**（那是猜），而本轮同步的是**主窗口当前显式选中的课程**（侧栏选择器 + 顶栏胶囊 + `?course=N` 本来就是同一个状态）。主窗口 `/assistant` 无参数仍然就是不限定课程，`effectiveScope()` 一行未改 —— **冻结点没被推翻**。
  - **主窗口在「全部课程」时同步 `null`**：否则会出现新的不一致（界面「全部课程」、球查某门课）。球的**自己的下拉仍然可用**（写同一个键，后写者为准），没有把选择权收走。
  - **`ball_set_course` 不 spawn**（同 R6 `get_courses`）：同步一个检索范围不该把应用拉起来。
  - **用户消息不做 Markdown 渲染**：用户输入的 `#` 就是 `#`，那是他的话，不该被当成标题。
- **本轮最该记住的两条**：
  1. **「界面写了什么，就必须按什么查」是双向的**。R6 修的是"球下拉为空"，R7 暴露的是它背面：按钮写着「先在**这门课**的材料 / 先验知识 / 知识点里查」，而球的范围默认是**全库** —— 面板那行「范围：全部课程（本机）」是诚实的，**承诺与行为不一致的错在按钮**。处置办法不是改文案（把"这门课"改成"全部课程"就等于承认球做不到按课检索），而是**把范围接上**。
  2. **R6 预留的 CSS 是照着"想象出来的类名"写的**：`.msg-bubble .md-code` 对应的 `md-code` **根本不存在**（渲染器产出 `md-pre`）、标题只覆盖 h2/h3/h4、`.md-list` 实际是渲染器产出的 `<ul>/<ol>` 本体。**没接线就没法验证**，这套规则因此躺了一整轮。真正的教训是：**先接线，再写样式**，否则样式是"对着草稿纸写"。
