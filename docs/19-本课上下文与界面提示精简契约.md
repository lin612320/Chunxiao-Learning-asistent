## 一、主界面提示信息：**删除**，不是改写

### 1.1 先纠正上一轮的理解偏差（如实记录）

R7 我把这些文案**改写成了大白话**（`docs/18` §一）。用户的真实要求是**删掉** ——
"界面不该向用户解释它是怎么实现的"。本轮按"删"执行：**能删的整句删掉**，只留功能名与一行可操作信息。

### 1.2 本轮删掉的（逐条）

| 位置 | 删掉的原文 |
| --- | --- |
| 题库 · 知识点空态 | 「点上面的「生成知识点清单」，春晓会按这门课已有的知识骨架列一份清单（已经有的不会重复加）。也可以直接去「生成题目」，不过出题时知识点名称要完全对得上，所以先把清单建出来更稳。」→ **只留「这门课还没有知识点。」** |

### 1.3 刻意**保留**的（并说明理由）

- **诚实边界一句没删**：`不是强化学习` / `模型权重不会因此改变` / `数据只在这台电脑上` /
  「AI 生成 · 待核对」徽标 / 「无材料出处，请自行核对」/ 「不面向考试场景」。
  理由：这些不是"解释实现"，而是**安全声明**；契约要求逐字，冒烟脚本也逐字断言（`docs/14` §C-4）。
- **折叠「说明」区（`<TechNote>`）里的工程口径一处没删** —— 那里是设计上唯一允许写实现细节的地方。
- **可操作信息保留一行**：「还没填模型 Key，暂时不能生成」+「去「数据设置」配置 →」链接。
  删掉"原因说明"不等于让用户卡在空状态里。

> ⚠ 如果用户要连诚实边界一起删，那是**契约级改动**（`docs/00` §7 与多个冒烟断言），需要单独拍板。

## 二、真缺陷：模型**不知道自己在哪门课里**（IR 那个回答的根因）

### 2.1 现场证据（2026-09-24，读用户本机库的副本，未改动原件）

```
courses:        2 数据库系统 / 3 计算机系统基础
course_prior:   课程 2 = 16 条（source=ai）；课程 3 = 0 条
materials:      0 条（整库一个材料都没有）
chat_sessions:  3（course_id=3, origin=app, 标题「什么是IR」）
chat_messages:  source_kind = no_material
                正文首句「未在你的本机课程材料中找到"IR"的条目。以下为模型补充，无材料出处，请自行核对」
```

**程序没有骗人**：0 命中这件事本身就是如实标注的。问题在于**模型拿到的上下文太薄**：

```js
// 修前（useChat.ts）
const sys = sysExtra ? `${systemPromptFor(mode)}\n\n${sysExtra}` : systemPromptFor(mode);
```

`systemPromptFor(mode)` 只有固定人设 + 任务；课程上下文**唯一的入口**是「先查材料」命中后的
材料片段块（`buildMaterialBlock`）。所以当这门课材料为 0 时，模型收到的信息等价于：
*「你在做课后答疑」+「什么是IR」* —— **完全不知道这是《计算机系统基础》**，
于是把 IR 当成通用缩写，列了 Information Retrieval / Intermediate Representation / 国际关系 / 红外……

### 2.2 修法：把「本课上下文」注入系统提示词

新增 `src/lib/courseContext.ts`：

| 项 | 内容 |
| --- | --- |
| 内容 | `【本课上下文】` + 课程名 + 「理解术语/缩写时**优先按这门课的语境取义**，若本课语境里不是它最常见的含义，先说明你按哪种含义理解」 |
| 附带 | 该课**知识骨架的条目名**（最多 40 条，仅列出名字），并**显式标注「由 AI 生成、尚未与你核对；只用来说明范围，不要当成事实依据引用」** |
| 拿不到课程名 | 返回空串 → **不注入**（注入一句"你在某门课里"等于没说，还占上下文） |
| 读骨架失败 | 只跳过这一块，**绝不拦住提问**（它只是语境，不是依据） |
| 注入时机 | 提到 `if (useMaterials)` **外面**：关掉「先查材料」也要知道自己在上哪门课 |

**与既有红线的兼容**（一条都没松）：这一块**只限定语境、不提供新知识依据**；
「有出处才许引用、无出处的补充必须标注」的规则原样保留（`docs/00` §7.3）。

### 2.3 边界（如实记录）

- **只修了主窗口对话页**。悬浮球的「问询」走 Electron 侧的 `floating-ball/src/main/ai.js`，
  **同样没有课程名**，本轮未改（球侧需要把课程名随 `task:run` 一起传给 `ai.js`）。→ 记为新的 backlog。
- 提示词内容**在本仓没有自动化断言**（它是发给模型的文本，界面看不到）——
  这与 `priorgen.ts` / `questions.ts` 的提示词现状一致，靠"口径写死在这里，改文案请同步契约"的注释约束。

## 三、**未实现**的需求：建课时按课程名联网搜索（需要拍板）

### 3.1 现状（必须说清，不含糊）

- 全仓**没有一行联网检索代码**；界面反而明确写着「正在本机检索课程材料…（**不联网**）」。
- `docs/00` §11.1 待决事项第 4 条**至今挂着**：
  「**先验知识的知识源**：仅靠模型生成，是否还要接公开课程大纲/教材目录（涉及来源合规）？」
  —— 这是**没拍板**的决策，不是"已完成但坏了"的功能。
- 现在建课时真正发生的是：「AI 生成知识骨架」→ 把**课程名 + 已导入材料的文件名/标题**交给模型 →
  模型凭**自身知识**产出骨架 → 预览确认后才入库（来源标 `ai`，`verified=0`）。
  课程 3 的骨架是 **0 条** → 说明这一步**没执行过**（或没确认保存）。

### 3.2 三个可选项与代价（等用户拍板，本轮不擅自实现）

| 方案 | 做法 | 代价 / 需要拍板的事 |
| --- | --- | --- |
| **A. 不联网（现状）** | 用模型自身知识生成骨架 | 零改动、零成本；但新课程/冷门课程骨架可能空泛或跑偏。**先做这一条就有用**：给课程 3 跑一次「AI 生成知识骨架」 |
| **B. 接搜索 API** | 建课时按课程名调搜索（Bing / Brave / Google CSE 等），把摘要喂给模型生成骨架 | 需要**第二个 Key**（搜索服务）；来源要标 `web` 并**逐条可回链**；`docs/00` §7.4 的版权口径要重写（"绝不回传"这条会变） |
| **C. 用模型的联网能力** | 走平台自带的联网/插件（如通义、智谱的联网工具） | 取决于用户配的平台是否支持；DeepSeek 的 `chat/completions` **不做联网**，需要换模型或换平台 |

⚠ 三者都会**打破界面现有的「不联网」承诺**（B/C），必须同步改 `docs/00` 的决策基线与界面文案 ——
这是产品口径问题，不是实现问题，所以本轮**没有擅自开工**。

### 4.1 本轮踩到的坑（值钱的两条）

1. **调试版 exe 不刷新 → 第 8 步整层红**（R6 记过的同一个坑又踩了一次）：
   我加了新命令 `ball_set_course` 却只跑了 `cargo check`（**不产出 exe**），
   于是真机冒烟用旧 exe 跑，`Command ball_set_course not found` 刷了 3 条 console error →
   「页面无 console 报错」断言红、第 8 步 exit 1。
   **规矩：真机验证前必须 `cargo build`。**
2. **尽力而为的后台同步不能用 `callRust` / `invokeStrict`**：这两个封装失败时都 `console.error`，
   而真机冒烟把 console error 当失败 → 一次**版本不匹配**会把整层打红（那是假红，指向的不是功能坏了）。
   所以 `ballSyncCourse` 改为直接 `invoke` + `console.warn`。
   ⚠ 那条红**不是没用的**：它恰好证明了真机层在守着"前后端命令名必须一致"。
