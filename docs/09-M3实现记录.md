## 一、交付内容

### 1.1 T2：最小 Markdown 渲染器（前端，**零依赖**）

`src/lib/markdown.tsx`——支持 ATX 标题、有序/无序列表（含一层嵌套）、``` 代码块、行内代码、粗体/斜体、`>` 引用、`---` 水平线、**表格**、链接、段落。

- **块划分与渲染一一对应**：每块渲染时带 `data-block={index}`，索引与 `splitBlocks()` 完全一致——这是批注锚点的地基。
- **安全**：全部 React 元素渲染，**无 `dangerouslySetInnerHTML`、无 HTML 拼接**；链接只允许 `http:`/`https:`/`mailto:`，其余降级为纯文本。

### 1.2 笔记（前端 + Rust）

| 项 | 内容 |
| --- | --- |
| Rust | `notes` 表新增 `source` 列（`ensure_column`，默认 `'user'`）；命令 `notes_list / note_get / note_save / note_update / note_delete / note_export_docx` |
| 列表 | 标题 / 日期 / **来源徽标**（`ai_session` → 「AI 整理 · 待核对」；`user` → 「自己写的」）/ 已导出标记 |
| 生成 | 收集**该课程当天**的会话消息 → 模型产出 Markdown 笔记（术语与公式、**存疑处标「待确认」**）→ **可编辑预览 → 点保存才入库**（`source: "ai_session"`）。**没有当天记录时如实提示**；**未配 Key 时按钮禁用**，不用模板冒充 AI 整理 |
| 导出 | **md**（浏览器下载）/ **.docx**（Rust 生成）/ **PDF**（`window.print()` + 只打印正文的打印样式，按钮旁如实标注「通过浏览器打印 → 另存为 PDF」） |

### 1.3 批注与高亮（本轮最容易做错的部分）

- `annotations` 表新增 **`block_index`** 列（`ensure_column`）——原表只有全文字符偏移，Markdown 重排后会**静默错位**。
- **锚点 = 块序号 + 块内字符偏移 + 原文片段（`quote`）**，三者合起来才算一个锚。
- **自愈三态**（`resolveAnnotations()` 是纯函数，预览与桌面走同一套代码）：
  1. 精确命中 → 原位渲染；
  2. 对不上 → 先在**本块**内搜 `quote`，再退化为**全文**搜索（按"离原块序号越近越优先"排序，结果稳定）→ 界面标**「位置已自动修正」**；
  3. 全文找不到 → 进「**已失效的批注**」独立列表（显示原文 + 备注 + 可删除），**不画在正文上**——不假装它还在原位。
- **关键词高亮**（阅读辅助、**不落库**）复用 `src/lib/highlight.tsx`，未改其接口。
- 偏移计算：选区两端在同一块内时用 `Range.toString()` 数块内纯文本偏移，**跨 `<strong>/<code>/<mark>/<a>` 精确**；跨块取不到单块区间 → 退化为「起始块整块」并在面板上**红字说明**（不静默降级）。

## 二、集成阶段发现并修掉的问题

### 2.1 ⚠ 中断留下的那条红单测：实现是对的，测试写错了（我已定位到行）

**现象**：`cargo test --lib` 40 passed / 1 failed，失败信息与测试名**不符**：

```
thread 'db::tests::focus_start_rejects_unknown_kind' panicked at src\db.rs:3337:9:
assertion `left == right` failed: limit < 1 按 1 处理
```

**两个问题叠在一起**：

1. **测试名比内容窄**：该测试体内其实是**完整的番茄钟全流程**（非法 `kind` 被拒 + `kind` 规范化 + 列表/结束/错误分支 + 倒序 + limit 边界），并非只测"拒绝非法 kind"。
2. **断言期望值与自己的说明自相矛盾**（真正原因）：`assert_eq!(focus_list(&conn, Some(0)).unwrap().len(), 2, "limit < 1 按 1 处理")`——实现是 `clamp(1, 上限)`，`Some(0)` 返回 **1** 条；消息也说"按 1 处理"，期望值却写 2 → **期望值是粘贴错误**（多半从"不带 limit 有 2 条"那条用例复制而来）。

**修法**（`db.rs`）：期望值 `2 → 1`，并**在断言处写明**"`limit<1` 被 `clamp(1,上限)` 夹到 1，不要再改回 2"（防止后人误"修"）；测试改名为 `focus_crud_validation_and_limit` 以符合内容。修后 **41/41 全绿**。

### 2.2 ⚠ `markdown.tsx` 缺 React `key`（实现代理发现并最小修复）

`blocks.map((b, i) => renderBlock(...))` 返回的元素**没有 `key`** → React 每次渲染都打 `console.error: Each child in a list should have a unique "key" prop`。

**为什么必须修**：`scripts/smoke-ui.mjs` 的「页面无 console 报错」断言**不过滤 React 警告**，接线 `/notes` 后闸门第 7 步会因此变红。代理做了**对照实验**（干净 profile 下：不加修复必现、加了零报错）确认不是 HMR 假象，然后用 `<Fragment key={i}>` 包裹（不产生 DOM 节点，`data-block` 结构不变）。

> 这条是"验证层反过来推动了修复"的例子：如果没做 UI 冒烟，这个警告会一直挂在控制台里而没人注意。

### 2.3 我自己的脚本缺陷：UI 冒烟"起不来 vite"（已修）

`verify-m0.ps1` 第 7 步曾报「vite 未在 60s 内就绪」。实测根因有两层：

1. **超时太紧且会被饿穿**：并行跑 `tsc` / `vite build` 时，`npm → vite` 的启动被拖慢（日志显示 vite 实际只差几秒就绪，`ready in 1456ms` 是启动后的耗时）；
2. **失败路径不回收进程**：超时后没杀掉自己起的进程链 → 留下**孤儿 vite 占着 1420**，下一次运行会误判"服务不可达"再去起第二个。

**修法**：超时 60s → **150s**；失败路径**同样回收**进程链（按 `CommandLine` 含项目根路径精确匹配，不误伤用户自己的浏览器与别的 vite）。

### 2.4 把"文案存在"升级为"行为验证"（我改的断言）

番茄钟原来的断言只检查"有没有 `MM:SS` 文案"——**这证明不了计时器真的在跑**。改为真实交互验证：

```
[PASS] 能找到并点击「开始」
[PASS] 点击开始后倒计时真的在走        ← 2.6s 后读数必须变化
[PASS] 能找到并点击「暂停」
[PASS] 暂停后倒计时停住（既不走也不回退）  ← 1.8s 后读数必须不变
```

### 2.5 一处"假通过"断言（我在中断轮发现、本轮沿用修好的版本）

新板块的第一版断言里有一条「有生成/新建入口」，它在**占位页上也通过**——因为占位页说明文案里也含"创建/生成"这类词。已加**占位措辞探测器**（`未实现|占位|方案稿|待实现|M[0-9]\s*(实现|开放)`）作为硬断言，并要求真实特征文本。收紧后它立刻给出证据（当时报 `仍出现占位措辞：M3 实现`）。

### 2.6 一次"差点写进文档的假 bug"（流程教训）

中断轮我曾用临时正则 `ensure_column\(\s*"annotations"` 搜迁移代码，搜不到，一度判断"代理把新列加进了 `CREATE TABLE`、旧库无法升级（违反契约）"。**回源码核实后发现是我正则漏了首个 `conn,` 参数** —— 代码完全正确（`db.rs:403/406` 走 `ensure_column`，原始建表语句未改）。
**教训：grep 不到 ≠ 不存在**，凡要写进文档的结论先回源码确认。

## 六、M3 的诚实边界（对外口径务必一致）
