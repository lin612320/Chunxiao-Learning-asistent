## 二、悬浮球的检索范围必须跟着主窗口走（真缺陷）

### 2.1 根因：界面承诺「这门课」，实际查全库

球面板的按钮提示写着「**先在这门课的材料 / 先验知识 / 知识点里查**」，但球的 `courseId`
只来自**球自己那份设置** `settings.ball.course_id`（没选过就是空 = 不限定课程）——
`ball_context_of` 的注释明确写着「**不自动套用「最近课程」**，由用户在球面板上显式选择」。

于是：用户在《数据库系统》里划词点「关联知识点」→ 实际是**全库检索**
（面板会如实写「范围：全部课程（本机）」，但按钮承诺的是「这门课」）。
这是 `docs/11` §一 第 2 条明令禁止的那种不一致：**界面写什么，就必须按什么查**。

### 2.2 修法：主窗口把「当前课程」同步给球

新增命令 **`ball_set_course(courseId: Option<i64>)`**：

| 环节 | 行为 |
| --- | --- |
| 落盘 | `set_ball_course_id` 写 `settings.ball.course_id` —— 与球自己的下拉**写同一个键**（只有一份状态，不引入第二份） |
| 下发 | 复用已冻结的 `context` 载荷：`courses` / `courseId` / `courseName` + `cmd:"context"` + **`ts`**（`docs/17` §二 的形状，球面板走既有 `courses:sync` 分支消费，**无新 cmd 分支**） |
| 不 spawn | 与 R6 的 `get_courses` 一致：**同步一个检索范围不该把应用拉起来**（球没在跑时只落盘 + 留一条控制文件） |
| 读回校验 | 下发的是**库里的值**而不是入参：课程被删 / id 非法时如实退化成「不限定课程」，**绝不出现"库里是 A、下发是 B"** |
| `ts` 必填 | 球的轮询只在 `msg.ts > lastCmdTs` 时处理 —— 漏了这一个字段，整条命令会被**静默忽略**（"主程序说同步了、球毫无反应"，最难查的一类缺陷） |

**触发点**：`Sidebar.tsx` 在 `activeId` 变化、且课程列表已读完时调用一次
（切课程 / 深链接带 `?course=N` / 课程被删回落到「全部课程」都会同步）。

**语义（一句话）**：**球默认跟随主窗口当前课程**；你在球上手动改过之后，
直到主窗口再次切换课程为止都以手动为准。

### 2.3 与冻结口径的关系（别误读成"推翻了 `docs/11`"）

- `docs/11` §一 第 3 条「**不自动套用「最近使用的课程」**」**依然有效、一行没改**：
  主窗口 `/assistant` 无参数仍然就是「不限定课程」，`effectiveScope()` / `scopeTextOf()` 未动。
- 本轮改的是**球**，而且同步过去的不是"猜出来的最近课程"，而是
  **主窗口当前显式选中的课程**（侧栏选择器 + 顶栏胶囊 + URL `?course=N` 本来就是同一个状态）。

### 2.4 边界（如实记录）

- 主窗口在「全部课程」时同步 `null` → 球也回到「全部课程」。
  理由：否则会出现新的不一致（界面「全部课程」、球查某门课）。
- 球自己的下拉**仍然可用**（写同一个键，后写者为准）——没有把球的选择权收走。
- 主程序没在运行时，球保留上一次同步到的范围（下拉如实显示），**不会**为了同步把主程序拉起来。

## 三、对话页：输入区同宽 + AI 回复 Markdown 渲染

### 3.1 输入区与消息区同宽（根因是 `<textarea>` 从来没给 `width`）

`<textarea>` 不给宽度时，宽度由 `cols` 属性决定（默认 **20 字符 ≈ 190px**）；
而它外面那层 `.assistant-drop` 只是普通 block（不是 flex 子项），不会替它拉伸。
于是输入框比上面的消息区窄一大截（用户实测可见）。

**修法一行**：`.assistant-input textarea { width: 100% }`。
`.assistant-messages` 与 `.assistant-input` 都是 `.assistant-page`（flex column）的子项，
撑满同一容器 → 两者同宽。

### 3.2 AI 回复走 Markdown 渲染（**关闭旧债 T28**）

| 项 | 内容 |
| --- | --- |
| 接线 | `Assistant.tsx` 的助手气泡：`<div>{m.content}</div>` → `<Markdown text={m.content} terms={refTerms} />` |
| 渲染器 | `lib/markdown.tsx`（M3 · T2 那个，笔记页在用）——零依赖、**无 `dangerouslySetInnerHTML`**、链接协议白名单 |
| `terms` | 用**本轮检索词**：与回答下方「参考来源」里标黄的词是同一份，用户能对上"答案里哪个词来自我的材料" |
| ⚠ 用户消息 | **仍按纯文本渲染**（`white-space: pre-wrap`）：用户输入的 `#` 就是 `#`，不该被当成标题 —— 那是他的话，不是 Markdown |
| CSS | R6 预留的那几条 `.msg-bubble .md-*` 是照着**想象出来的类名**写的（`md-code` 根本不存在；标题只覆盖 h2/h3/h4；`.md-list` 实际是渲染器产出的 `<ul>/<ol>`，外面还有 `.md-list-wrap`）→ **整块按真实产出的类名重写** |
| ⚠ 关键一条 | 补 `.msg-bubble .md-body { white-space: normal }`：气泡是 `pre-wrap`（用户消息要保留换行），**不复位就会把 Markdown 源码里的换行漏进正文** |
| 超宽 | 表格在气泡里必然超宽 → 只让 `.md-table-wrap` 自己横向滚，不把消息区撑出横向滚动条 |

### 3.3 示例数据（断言的数据源）

`src/data/sample.ts` 会话 31 的那条示例回答**故意写成 Markdown**（`##` 标题 + 列表 + `**粗体**`）：
它既是冒烟断言的数据源（"渲染出真标题 / 真列表，且气泡里不再出现 `#` 与 `**`"），
也让预览模式一眼能看到渲染效果。
