## 一、已拍板的结构（用户三选一确认的结果）

| 项 | 结论 |
| --- | --- |
| 侧栏结构 | **课程优先**：侧栏只留「课程 / 专注计时 / 数据设置」；选中课程后展开该课的：课程总览 / 笔记 / 题库 / 与该课对话 / 学习画像；「全部课程」态给跨课程汇总（笔记 / 题库 / 画像） |
| 首页总览 | **删掉**，打开应用直接落在「课程」（`/` 与旧的 `/home` 都 301 到 `/courses`） |
| 提示力度 | **能删就删**：删掉重复的标题与口号，口径说明收进折叠「说明」区，**诚实边界一条不删** |

### 1.1 做法：**侧栏就是"这门课的功能列表"**，而不是把 4 个页面塞进课程页

`?course=N` 作为**唯一的课程上下文**（URL 优先，其次 localStorage 的 `chunxiao:last-course-id`，沿用 R1 的键）。
侧栏链接带上它：`/notes?course=3`、`/questions?course=3`、`/assistant?course=3`、`/profile?course=3`。

**为什么不把笔记/题库/对话/画像嵌成课程页里的标签页**：那要给 4 个页面组件各加一套"内嵌模式"
（标题要不要显示、高度怎么算、双层 shell 会不会打架），改动面大且容易藏出"标题重复 / 高度算错"这类问题。
现在这样语义一致（**进了这门课，侧栏列的就是这门课的功能**），风险小得多。

### 1.2 课程的可见性

- **侧栏顶部课程选择器**：整条侧栏的入口，切换时**留在当前版块**（在「笔记」里换课程 → 还是「笔记」）；
- **顶栏课程胶囊**：导航改成课程优先之后，"我在哪门课里"必须**始终可见**；
- 课程被删 / 换库时**自动回到「全部课程」**，并诚实提示"没读到课程"（不留一个指向不存在课程的选中态）。

## 二、第 1 条：悬浮球课程列表恒为空（真 bug）

### 2.1 根因

课程列表原先**只在主程序主动 push 时**才到球里（`ball_show` / `ball_prefill` 会带 `courses`），
而用户**点球 / 按热键 / 双击托盘**打开面板走的是 `ball:click → togglePanel`，**没有任何推送** ——
球内存里的 `courseCache.courses` 永远是 `[]`，下拉里一门课都没有。

### 2.2 修法：球**主动要**

| 环节 | 行为 |
| --- | --- |
| 球 → 主程序 | 新增 `action:"get_courses"`（**不 spawn 主程序**：填一个下拉不该把整个主程序拉起来） |
| 触发时机 | ① 面板 `init`；② **每次点开课程下拉**；③ 点球 / 热键 / 托盘打开面板时 |
| 主程序 → 球 | 回传 `{cmd:"context", courses:[{id,name}], courseId, courseName}`（复用 R4 已有的 `courses:sync` 通道，**无需新 cmd 分支**） |
| 空列表 | 面板必须**说清是哪一种空**：`（正在读取课程…）` / `（还没有课程）`，并在范围提示里给出可操作指引 |

> ⚠ 主程序**没在运行**时球不会自行拉起它（`spawn:false`），此时下拉如实显示"正在读取…"并保持不动 ——
> 不假装有数据，也不为填一个下拉而启动一个应用。

### 2.3 实测证据（2026-09-24）

```
写入 from-ball.json: {"text":"","action":"get_courses","ts":...}
0.98 秒后 to-ball.json:
{"cmd":"context","courseId":null,"courseName":null,
 "courses":[{"id":3,"name":"计算机系统基础"},{"id":2,"name":"数据库系统"}],"ts":...}
```

## 三、第 3 条：课程优先的信息结构（实现口径）

| 位置 | 全部课程态 | 某门课态（`?course=N`） |
| --- | --- | --- |
| 侧栏导航项 | 课程列表 / 全部笔记 / 全部题库 / 学习画像 | 课程总览 / 笔记 / 题库 / 与该课对话 / 学习画像 |
| 笔记页 | 显示「按课程筛选」下拉，标题「全部笔记（N）」 | **隐藏筛选器**（侧栏已选过课），标题「本课笔记（N）」，列表只含该课 |
| 题库 / 画像 | 同前（各自的课程筛选保持可用） | 同上（锁定） |
| 对话页 | 会话列表 = `origin='app'` 的全部会话 | 会话列表 = 该课 + `origin='app'`（R5 已实现） |

**删掉的**：`NAV_ITEMS`（静态列表表达不了课程上下文）、`views/Home.tsx`、对话页的「在聊哪门课」选择器
（课程已由侧栏 + 顶栏负责，页内再放就是三处重复）、每页标题下那句 `hint`。

## 四、第 2 条：去噪（能删就删）

- 顶栏：删掉 `PAGE_HINT`（每个页面标题下那句说明）；
- 对话页：删掉重复的页内标题「与春晓对话」与口号「面向课后理解与复习 · 不面向考试场景」，
  只留两个如实的小标签（「演示模式」「数据都在这台电脑上」）；
- 笔记页：删掉页内 `<h2>笔记</h2>` + 那段解释 + 「本地单机 · 数据在本机」标签（侧栏页脚已有）；
- 各页内边距由 `32/40/56` 收到 `20/24/24`（省下的高度全部给内容区，见 §六）；
- **保留**：所有诚实边界（不做本地 OCR / 未配 Key 是演示模式 / AI 生成待核对 / 掌握度是统计量…），
  它们要么是短标签、要么在折叠「说明」区里 —— **一句都没删**。

## 五、第 4 条：笔记支持随时手动写入

- 笔记页新增 **「＋ 新建笔记」**：标题 + 正文（Markdown）编辑区 → 保存；
- **不复用"先建一条空笔记"的路子**：`noteSave` 在 Rust 侧要求**标题与正文都不为空**（诚实口径），
  所以先让用户写、写好了再入库 —— 与"生成草稿 → 确认才保存"同一套纪律；
- 来源标 **「自己写的」**（`source:'user'`），与 AI 整理的「AI 整理 · 待核对」在界面上**一眼可分**；
- 归属课程：锁定的课程优先，否则用生成区选的那门，最后兜底第一门未归档课程；
  一门课都没有时按钮禁用并给出原因（不静默失败）。

## 六、第 5 条：对话内容显示不全 —— 根因是**输入区把消息区挤扁了**

### 6.1 实测（1200×760，真机）

| 区块 | 改前 | 改后 |
| --- | --- | --- |
| 消息区 `.assistant-messages` | **190px** | **292px** |
| 输入区 `.assistant-input` | **278px** | **220px** |

**"窗口太小"其实是三处叠加**：

1. `.content` 的内边距 32 + 56 = **88px** 全被吃掉 → 收到 20 + 24 = 44px；
2. 输入区里塞了**两行**控制项（模式 chips 一行 + 「先查材料」开关一行，外加一句与 chip 的 `title` 重复的说明）
   → **合成一行**：`[答疑][出题][笔记][讲解]  [☑先查材料]  检索范围：…`（范围过长时省略号 + 悬停看全文，
   **仍在主界面可见**，满足契约 §一 第 2 条）；
3. 输入框 `rows=3` → `rows=2`。

### 6.2 没动的

- 消息气泡仍是纯文本渲染（模型返回的 Markdown 会原样显示）—— 这是旧债 **T28**，不在本轮范围；
- 引用来源 / 「本轮检索词」 / 「无材料出处」这些**如实标注**一条没删。
