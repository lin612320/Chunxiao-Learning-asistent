## 三、唯一失败单测的精确诊断（已定位到行，含修法）

**失败项**：`db::tests::focus_start_rejects_unknown_kind`（定义在 `db.rs:3296`）

**现象**：
```
thread 'db::tests::focus_start_rejects_unknown_kind' panicked at src\db.rs:3337:9:
assertion `left == right` failed: limit < 1 按 1 处理
test result: FAILED. 40 passed; 1 failed
```

**两个问题叠在一起**：

1. **测试名与测试体不符**：该测试体内其实是**完整的 focus CRUD + limit 测试**（start → list → finish → 非法 id → 负数时长 → 倒序 → limit），并不只测"拒绝非法 kind"。属命名/拆分错误。
2. **断言期望值与自己的说明自相矛盾**（真正的失败原因）：
   ```rust
   // db.rs:3337
   assert_eq!(focus_list(&conn, Some(0)).unwrap().len(), 2, "limit < 1 按 1 处理");
   ```
   实现 `focus_list` 是 `limit.unwrap_or(默认).clamp(1, 上限)`（`db.rs` 内），所以 `Some(0)` → **返回 1 条**；而断言期望 **2 条**，且**消息自己就写着"按 1 处理"** → 期望值是**粘贴错误**（多半是从"不带 limit 有 2 条"那条用例复制过来的）。

**结论：实现是对的，测试写错了。**

**修法（两处，都很小）**：
```rust
// ① 期望值改为 1（与消息、与实现一致）
assert_eq!(focus_list(&conn, Some(0)).unwrap().len(), 1, "limit < 1 按 1 处理");
// ② 把测试改名以符合其内容，或拆成两条：真正验"focus_start 拒绝非法 kind" + 一条 focus CRUD
```

## 五、本轮的另一处收获（已修，值得记）

**我自己的 UI 断言出现过"假通过"**：给新板块写的第一版里有一条「有生成/新建入口」，它在**占位页上也通过了** —— 因为占位页的说明文案里也含"创建/生成"这类词，断言根本区分不了真假页面。

**修法**：加**占位措辞探测器**（`未实现|占位|方案稿|待实现|M[0-9]\s*(实现|开放)`）作为硬断言，并要求真实特征文本（如番茄钟的 `MM:SS` 倒计时）。收紧后它立刻给出证据：

```
[FAIL] 笔记页已替换占位（无占位措辞） — 仍出现占位措辞：M3 实现
[FAIL] 番茄钟页已替换占位（无占位措辞） — 仍出现占位措辞：M5 实现
```

**教训**：断言必须能**区分"功能存在"与"文案里提到该功能"**，否则测试会给出虚假的安全感。

## 六、流程教训（我自己的，一并记下）

本轮我差点把一条**假 bug** 写进文档：我用正则 `ensure_column\(\s*"annotations"` 去搜迁移代码，搜不到，便一度判断"代理把新列加进了 `CREATE TABLE`、旧库无法升级（违反契约）"。**核实源码后确认是我 grep 写错了** —— 实际签名的第一个参数是 `conn`（`ensure_column(conn, "annotations", …)`），漏掉它自然搜不到；代码本身完全正确（`db.rs:403/406`）。

**教训**：**grep 不到 ≠ 不存在**，尤其是自己临时拼的正则；凡要写进文档的结论，先回源码确认一遍。
