| # | 用户原话 | 落到本契约 |

### 一条被用户明确划掉的边界（省下一整块新功能）

初稿曾计划做「区域截图 / 整窗截图 / 快捷键抓前台窗口」三档屏幕抓取。**用户明确否掉了**：

> 「这个你不用管，就我能粘贴我的截图就行」

因此本轮**不做任何屏幕抓取**：不引入 `desktopCapturer`、不新增全屏选区浮层窗口。
「抓取电脑窗口内容」这条需求由**既有能力**满足 —— 用户用系统截图工具（`Win+Shift+S`）截屏后
**`Ctrl+V` 粘进面板**（R4 已实现）。本契约据此**不登记**任何抓取相关接口。

## 一、数据模型

### 1.1 `chat_sessions.origin`（新增列，走 `ensure_column` 幂等迁移）

```
ALTER TABLE chat_sessions ADD COLUMN origin TEXT NOT NULL DEFAULT 'app'
```

| 值 | 含义 |
| --- | --- |
| `app` | 主窗口（对话页）产生的会话 |
| `ball` | 悬浮球面板产生的会话 |

**必须写清的一条历史事实**：R4 及以前的**球问答是被合并进主窗口会话的**
（`ball_append_qa` 复用该课程「最近更新」的会话）。那些历史消息**无法追溯来源**，
迁移时一律按 `app` 处理 —— 即**历史球问答仍会出现在主窗口列表里**，
本轮的分离**只对新增数据生效**。这里不假装能区分，也不做事后猜测。

### 1.2 为什么用"列"而不是"新表"或"新库"

- 用户要的是「**都要并入知识库里**」：同一个 `chunxiao.db`、同一套 `chat_messages`，
  这样「从本课对话提炼先验知识」「一键生成课堂笔记」能照旧读到球的问答；
- 新表会把这套复用链全部打断，得再写一份 join 与迁移；
- 一列 `origin` 即可表达来源，且**旧库平滑升级**（`ensure_column` 是 no-op）。

### 1.3 新增 settings 键

**无。** 全部新配置都留在**球自己**的 `%APPDATA%\chunxiao-ball\config.json`：

| 键 | 含义 |
| --- | --- |
| `panelWidth` / `panelHeight` | 面板尺寸记忆（用户拖过就记住） |
| `panelCollapsed` | 是否处于「收起」态 |

> 理由：窗口尺寸是**纯前端外观偏好**，与课程/知识库无关，走桥接只会增加跨进程竞态。

## 二、命令契约（Rust）

### 2.1 `chat_sessions_list` 增加**可选**参数 `origin`

| 项 | 口径 |
| --- | --- |
| Rust 形参 | `origin: Option<String>` |
| JS 传参 | `origin?: "app" \| "ball"`；**不传 = 不过滤**（返回全部） |
| 返回行 | 新增 `"origin": String` 字段（值必为 `app` \| `ball`） |
| 非法值 | **返回可读中文错误**，不静默降级为"全部" —— 静默会让"我明明只筛了球"变成"看到一堆主窗口会话" |

**向后兼容**：现有唯一调用点（`src/hooks/useChat.ts`）不传 `origin` 时行为与今天**逐字一致**。

### 2.2 `ball_append_qa` 的落库口径**变更**

| 项 | 旧（R4） | 新（R5） |
| --- | --- | --- |
| 目标会话 | 该课程 `course_id` **最近更新**的会话（可能是主窗口的） | 该课程 `course_id` 且 **`origin='ball'`** 的最近会话 |
| 无匹配时 | 新建，标题「悬浮球问答」 | 同上（**新建会话 `origin='ball'`**） |
| 主窗口影响 | 球的问答会出现在主窗口会话里 | **不再出现**（主窗口默认只列 `origin='app'`） |

其余口径**不变**：`course_id` 指向的课程不存在时退化为「不限定课程」并打日志（不丢问答）；
`source_kind` 仍固定 `ball_ask` 便于溯源；`images` 仍走同一道 6 MB 上限。

### 2.3 新增命令 `knowledge_match`

供**主窗口**（以及将来的课程页）复用同一条关联检索；球侧走桥接（§三），逻辑同源。

| 项 | 值 |
| --- | --- |
| 参数 | `courseId: number`、`text: string`、`limit?: number`（默认 8） |
| 返回 | `{ kw: string, materials: [{material, page, snippet}], priors: [{id, topic, summary}], kps: [{id, name}] }` |
| 空结果 | 一律返回**空数组**（契约 `docs/01` §四.1） |

## 三、悬浮球桥接载荷（**新增 action**，逐条登记）

### 3.1 球 → 主程序（`from-ball.json`）

| action | 载荷 | 语义 |
| --- | --- | --- |
| `relate_search` | `text, course_id` | 「关联」第一步：**只查不写** |
| `relate_save` | `course_id, items[], source_ref?` | 「加入本课知识点」：**整批事务写入** `course_prior` |

`items` 元素形状**与 `prior_add_tree` 逐字一致**（`docs/11` §2.3 已登记的口径例外，
嵌套载荷跟随草稿结构、允许 snake_case）：`{topic, summary?, detail?, parent_topic?}`。

### 3.2 主程序 → 球（`to-ball.json`）

| cmd | 载荷 | 说明 |
| --- | --- | --- |
| `relate_result` | `{ts, cmd, kw, courseId, materials:[{material,page,snippet}], priors:[{id,topic,summary}], kps:[{id,name}], note?}` | 对应 `relate_search` |
| `relate_saved` | `{ts, cmd, ok:boolean, count:number, ids:number[], error?:string}` | 对应 `relate_save` |

> `materials` 的形状**沿用 `material_result` 已冻结的字段名**（`material` / `page` / `snippet`），
> 不新造一套 —— 球侧同一段渲染代码可以复用。

### 3.3 `relate_save` 的入库口径（红线）

1. **`course_id` 必填**：`null` / 缺省一律**拒收**（可读中文错误）。
   理由：先验知识**必须归属某门课程**（`course_prior.course_id` 是 `NOT NULL`），
   「不限定课程」是一个**检索范围**概念，不是一个可以入库的归属。
2. `source` 由主程序**写死** `球抓取`，`source_ref` 取球传来的原文摘要（可空）。
3. `verified` 硬编码 `0`、`confidence` 不填 —— 与 `prior_add` / `prior_add_tree` 同一红线：
   **AI 抽出来的候选只有用户核对过才算数**。
4. 整批**同一事务**：任一项非法（`topic` 空 / 超 200 字 / 父知识点不在本批）→ **全部回滚**，
   错误里指出是第几项（复用 `prior_add_tree` 的既有实现，不另写一份校验）。
5. 球侧**必须先让用户确认**（可勾选、可编辑）才发 `relate_save` —— 不做"抓取即自动入库"。

## 五、悬浮球面板（`panel.html` / `panel.js` / `windows.js`）

### 5.1 排版：结果优先

| 位置 | 内容 |
| --- | --- |
| 顶栏 | 品牌 + 记录/换肤/主题/设置/隐藏（图标行） |
| 课程行 | 「课程：[下拉]」+ 一行如实说明（当前范围） |
| **结果区** | **`flex:1` 占满剩余高度**（旧版被压到最小 100px，是"排版问题"的主因） |
| 输入区 | 正文框（1–4 行自适应）+ 图片缩略图条 + **两个按钮：`问询` / `关联知识点`** |
| 抽屉 | 设置（平台/AI 配置/快捷键/抓取模式）—— 保持折叠，不占主界面 |

### 5.2 可缩放

- 窗口 `resizable: true`，`setMinimumSize(360, 420)` / `setMaximumSize(900, 1200)`；
- **尺寸看门狗改为"钳制"**：旧实现把最小=最大写成固定值、并在 `resize` 事件里**强制拉回**，
  这是"不能缩放"的根因。新实现只在**越界**时拉回，用户在范围内的缩放**被允许**；
- 尺寸变化 300ms 防抖后写入 `config.panelWidth/panelHeight`；下次启动按它开窗。

### 5.3 可收起

- 顶栏一个「⇕」按钮：收起态高度固定 **56px**（只留一行：输入框 + `问询` + `关联`），
  再点还原到记忆高度；状态存 `config.panelCollapsed`，启动时恢复。

### 5.4 「关联知识点」交互（三段式，**每一段都如实显示**）

1. **查**：点按钮 → `relate_search` → 结果区分三块显示命中（材料片段 / 先验知识 / 知识点）；
   命中 0 条也要**说清是"没查到"而不是"没查"**（带 `note`）；
2. **抽**：结果区下方出现「从这段内容提取知识点，加入本课」（**课程未选时禁用**并说明原因）；
   点击后走球侧 AI，用**结构化输出**列出候选（`topic / summary / detail / parent_topic`）；
3. **确认**：候选以**可勾选 + 可编辑**的列表呈现，点「加入本课」才发 `relate_save`；
   回传 `relate_saved` 后如实显示入库条数或错误原文。

### 过程中踩到并修掉的 4 个真问题

1. **`edit` 工具会把 `.ps1` 的 UTF-8 BOM 去掉**（实测写出后的前三字节是 `23 20 E6`，即 `# ` + 中文）。
   本项目对 `.ps1` 有硬性 BOM 要求（闸门第 6 步会拦），所以**改过任何 `.ps1` 之后必须复检 BOM**；
   补 BOM 一定要用**两侧都显式指定 UTF-8** 的读写（`ReadAllText/WriteAllText` + `UTF8Encoding`），
   用 `Get-Content -Raw | Set-Content` 会因为读取时按 ANSI/GBK 解码而**把整份中文变成乱码**（本轮真踩过一次，已从 git 还原重做）。
2. **悬浮球面板此前完全不能缩放**：`windows.js` 用 `setMinimumSize(w,h) = setMaximumSize(w,h)` 把窗口钉死，
   并在 `resize` 事件里强制拉回 —— 这是"排版问题"之外的另一半根因（用户只能被动接受 420×620）。
   改法：只给上下限 + 看门狗**钳制**；同时在拖顶栏的路径上复核并还原尺寸，保住 R2 那次"越拖越大"的修复。
3. **`relate:save` 失败时不能把候选列表清掉**：第一版在成功分支里先 `clearCandidates()` 再往已被移除的节点里写提示，
   结果是"写进去了却什么都不显示"。改为成功替换、**失败保留候选并放开按钮**（用户改完能重试）。
4. **`chat_sessions_list` 的旧调用点全部要改签名**：Rust 侧 3 处测试调用点直接编译失败 ——
   这正是"接口变更必须全量编译"的价值，比运行期静默少一列要便宜得多。

### 一处能力边界（如实记录）

- 沙箱环境的**进程沙箱**禁止以管道 stdio 启动子进程，而 `esbuild`（`vite build` / `vite dev` 都依赖）正是这么启动自己的服务进程的，
  表现为 `Error: spawn EPERM`。这是**环境限制，不是代码缺陷**：放开权限后同一条命令 exit 0、83 个模块正常打包。
  第 7、8 步（要起 vite）同理 —— 环境受限时脚本会记 SKIP 而**不冒充通过**。

## 九、R5.1 事故复盘：面板「收起」把用户卡死（0.7.1）

### 9.1 用户原话

> 「你都不给我问什么的输入框，只让我点问询我要问什么？」
> 「这个收起你是用哪个部位想出来的？收起以后 ui 怪异不说我甚至没法取消收起」
> 「我要的是有一个框可以拖入文本，再一个框可以写我要问什么，然后有一个按钮可以点击关联知识点，就这些」
> 「然后手动和自动抓取你也给我弄没了我真服了」

用户机器上的配置（诊断证据）：

```json
{ "panelHeight": 64, "panelCollapsed": true, "panelWidth": 360 }
```

### 9.2 根因：**三条抱怨其实是同一个错误**

| 现象 | 直接原因 |
| --- | --- |
| 没有"问什么"的输入框 | 面板**卡在收起态**：64px 的窗口里只剩一个 38px 高的输入框细条，没有标签、没有按钮 |
| 收起了就没法取消 | 收起态内容（输入框 38 + 按钮行 38 ≈ **100px**）**装不进 64px**，按钮行被裁到窗口外；而「展开」按钮**恰好就在那一行里** |
| 重启也没用 | `panelCollapsed` 被持久化，每次启动都恢复成收起态 |
| 自动/手动抓取"没了" | 那一版把它换成了**顶栏的一个纯图标按钮**（🔄/✋），没有文字、只有悬停提示；收起态下顶栏又被整块隐藏，等于彻底消失 |

**决定性缺陷**：把"恢复入口"放在了"会被裁掉的那一行里"。任何"隐藏 UI 的功能"都必须保证**恢复入口永远可见**。

### 9.3 修法（R5.1）

1. **整块删除「收起」**（用户没要过，是我加的）：`panel:set-collapsed` IPC、`windows.applyCollapsedSize`、
   `PANEL_COLLAPSED_H`、`config.panelCollapsed`、渲染层的 `.collapsed` 规则**全部删干净**。
2. **配置自愈**（`config.load()`）：删掉 `panelCollapsed` 键；`panelHeight` 低于下限就拉回默认值。
   —— 否则升级后旧配置里的 `panelHeight: 64` 会让面板**依旧是那道残疾窄条**（已实测到过）。
3. **按用户说的做两个框**：`#source`「抓取的内容」（拖入 / 划词自动填 / 截图 `Ctrl+V`）+ `#question`「我要问什么」
   （**回车=问询、Shift+回车=换行**；输入法组合态 `isComposing` / `keyCode 229` 时不发送，否则选词的回车会把半截拼音发出去）。
   问询时内容作**上下文**、问题作**问题**；两个框都有内容时，落库记录会把原文（截断 2000 字并如实标注）一并存下。
4. **抓取模式恢复成两个带文字的按钮**（`🔄 自动抓取` / `✋ 手动拖入`），常驻正文，与设置抽屉双向同步。
   —— **结论**：带文字的功能入口不要收成图标按钮；图标按钮在这个产品里已经被否过两次（R3 主窗口 emoji 换 SVG 是同一类问题）。
5. **版面加固**（都是实测出来的，不是推理）：
   - **按钮行移出可压缩区**（`.compose` 之外、`flex:0 0 auto`）→ 面板再小也**不会把它裁掉**；
   - **结果区是唯一允许伸缩的一块**（`min-height:44px`），两个输入框按内容定高、**不参与压缩** ——
     第一版让它们一起压缩，实测出现"源框底 342 / 问题框顶 346"的**重叠**；
   - 输入框高度上限**随视口**（`min(150, 24vh)`，`resize` 时重算），长内容不会把结果区挤没；
   - 面板最小高度 **420 → 460**（420 时结果区只剩 36px，仅够一行）；
   - 结果行的 `⧉`(U+29C9) 在 Segoe UI 里**没有字形、渲染成白方块**（截图里亲眼看到）→ 换内联 SVG。
6. **新增版面守门并进闸门第 9 步**：`scripts/smoke-ball-panel.ps1` + `.mjs`（无头 Edge + CDP，渲染 `panel.html` 本身）
   断言：六个关键控件都存在且**完整落在窗口内**、互不重叠、页面无溢出、两个框都有可见标签、
   抓取模式按钮**带文字**。最小尺寸（360×460）与默认尺寸（420×620）各跑一遍。
