## 一、M0 目标是"可运行骨架"，不是"能演示的功能"

验收标准（评估文档 §9）：

> 桌面版能跑起来：**划词 → 悬浮球面板 → 问 AI → 有回答**；课程能建、能看先验知识（带来源标注）、能配 BYOK。

因此 M0 **只做骨架与真链路**，M1+ 的功能（材料导入与切块检索、笔记、题库、画像、番茄钟、桌宠）一律**占位并如实标注**，不做假实现。这条纪律在实现里被反复执行：材料导入按钮写"M1 开放"、PDF/图片解析返回"将在 M2 支持"、笔记/题库页写"未实现"、演示模式回复写明"这不是 AI 的回答"。

## 二、实现决策（不写代码也能看懂的取舍）

| # | 决策 | 理由 |
| --- | --- | --- |
| D1 | **不内置共享 API Key**（BYOK） | 母本内置了共享 Key 让分发版开箱即用，但学生产品会造成不可控账单与滥用。已删除母本 `keycrypt.js` 的默认 Key 密文，`getDefaultApiKey()` 恒返回空串；未配置时面板给出可读提示而非假装能答 |
| D2 | **保留母本目录名 `floating-ball/`**，只改包名与数据目录 | 目录名用户不可见，保留可降低搬运摩擦；包名 `chunxiao-ball` 决定 Electron userData = `%APPDATA%\chunxiao-ball`，与母本完全隔离（可同时运行互不干扰） |
| D3 | 桥接文件改名 `from-ball.json` / `to-ball.json`（母本为 `to/from-workbench.json`） | 按"以主程序视角命名"更直观；`workbench` 是母本（法律工作台）词汇，新项目应清掉 |
| D4 | **M0 不声明 Tauri 的 `float` 窗口** | 母本的 `float` 是"应用内置置顶小窗"。本产品悬浮球是外部 Electron 应用，已满足需求；少一个窗口 = 少一处要验证的状态机。前端仍实现 `?float=1` 紧凑模式，为将来留口 |
| D5 | M0 的 `tauri.conf.json` **不写 `bundle.resources`** | 悬浮球尚未打包成 `win-unpacked`，写不存在的路径会让打包直接失败。⚠ 实测教训：备注**不能**写成 `bundle._resources_note` —— Tauri 的 `BundleConfig` 是 `deny_unknown_fields`，未知字段会直接让构建失败；改放顶层 `plugins._resources_note`（HashMap，允许自定义键） |
| D6 | 图标用**原创几何占位**，不搬母本品牌标 | 母本图标是「法元」品牌标志；且鲸鱼素材有第三方权利瑕疵（评估文档 §4.3）。占位图 = 品牌色圆角方块 + 「春」字，纯程序生成 |
| D7 | 悬浮球面板的「关联查找**法规**」→「关联**课程材料**」 | 母本该按钮走主程序本地法条库。若原样保留，用户会看到"未找到相关**法条**"这种荒谬提示。已重命名整条链路（IPC 频道 `laws:ask`→`material:ask`、桥接 action `laws_search`→`material_search`、载荷字段 `title/article_no`→`material/page`），超时提示如实说明材料检索 M2 开放 |
| D8 | Rust 侧**不自动拉起悬浮球** | 母本在 `setup` 里自动 spawn 球，开发期反复弹窗很烦；改为用户点按钮触发 |
| D9 | **行字段 snake_case、命令参数 camelCase** | 返回 `Value` 时行键名与 SQL 列名逐字一致；参数侧用 Tauri v2 的自动映射。**这条两边不一致会导致字段静默读不到**，故写进契约 §四.1 冻结 |
| D10 | **api_key 加密职责在 Rust，前缀统一 `enc.`** | 前端桌面路径只传**明文**，Rust 加密落盘、`settings_get` 返回明文（母本口径）；浏览器预览才由前端 `secret.ts` 加解密。避免双重加密。母本用 `enc:`（冒号），本项目统一 `enc.`（点） |
| D11 | **AI 配置随控制命令同步给悬浮球**（本次联调新发现并修复，见 §三.3） | BYOK 下主程序与球各有一份配置，用户会被迫填两遍 |

## 三、联调中发现并修复的两个真问题

### 3.1 ⚠ BYOK 引出"要填两遍 Key"（功能缺陷，已修）

**问题**：主程序把 Key 存在 `settings` 表，悬浮球把 Key 存在自己的 `%APPDATA%\chunxiao-ball\chunxiao-ball-config.json`。母本靠**内置共享 Key** 掩盖了这件事——两边都开箱可用，用户从没感觉要填两遍。D1 拿掉内置 Key 后，这个隐患直接暴露：

> 用户在主程序「数据设置」配好 Key → 划词 → 在面板提问 → 面板回"未配置 AI API Key"。**M0 的验收路径直接被卡住。**

**修法（避开竞态）**：主程序与球之间只有一个控制文件，后写会覆盖先写，所以**不能**单发一条 `config` 命令再发 `show`。改为把 AI 配置**搭在命令上**一起下发：

```
{ ts, cmd: "show", ai: { baseURL, apiKey, model } }
```

- Rust 侧 `send_ctrl` 新增 `ai` 参数；`ball_show` / `ball_prefill` 下发前从 `settings` 读出配置（`ai_config_of()`，**apiKey 解密成明文**，因为球侧要用它发请求，球拿到后会用自己的盐重新加密落盘）；
- 球侧对**任意**控制命令都先处理 `msg.ai`（落盘 + 通知面板刷新），再派发 `cmd`；面板回填时**只填空字段**，不覆盖用户正在输入的内容。

**为什么必须解密**：若把 `enc.` 密文直接给球，球拿密文去请求会被网关判为无效 Key，且现象很隐蔽——用户看到的是"Key 无效"而不是"配置没同步"。已为此写了专门的单测（见 §四.6）。

### 3.2 冒烟脚本自身的 bug（已修，非产品问题）

`smoke-desktop.ps1` 初版用 `File.ReadAllBytes` 读 `chunxiao.db`，结果 6 项断言全 FAIL。原因有两条，都是 SQLite 的常识：

1. **WAL 模式下主库被运行中的进程独占** → `ReadAllBytes` 抛 IOException，`$bytes` 为 null，后续断言全部崩掉；
2. **新写的表/值先在 `-wal` 文件里**（未 checkpoint），只扫主库根本看不到 schema。

修法：`FileShare.ReadWrite` 共享读 + 合并 `chunxiao.db` 与 `chunxiao.db-wal` 再扫描。修后 PASS 8 / FAIL 0（主库 4,096 B + WAL 300,792 B）。

### 3.3 环境坑

**Electron 二进制下载被网络重置（`ECONNRESET`）**：npm registry 本身可达（`npm ping` → PONG 484ms），但 Electron 的 postinstall 要从 GitHub releases 下载约 100 MB 二进制，本机对该域名连接被重置。修法：母本（同版本 `electron@^33` + `uiohook-napi@^1.5.5`）的 `node_modules` 已装好，直接 `robocopy` 本地复用（296 包 / 543.9 MB）。备选：`$env:ELECTRON_MIRROR="https://npmmirror.com/mirrors/electron/"`。

**PowerShell 5.1 的 `.ps1` 必须带 UTF-8 BOM**：本机 `pwsh` 不在 PATH，harness 用 Windows PowerShell 5.1 执行。含中文的 `.ps1` 若无 BOM，会被按系统代码页（GBK）解码，报出**与行内容毫不相关**的解析错误（如"函数参数列表中缺少 )"）。项目规范：

```powershell
$t = [System.IO.File]::ReadAllText($p, [System.Text.UTF8Encoding]::new($false))
[System.IO.File]::WriteAllText($p, $t.TrimStart([char]0xFEFF), [System.Text.UTF8Encoding]::new($true))
```

（"先剥再写"可保证恰好一个 BOM——`ReadAllText` 的 BOM 处理有歧义。）
