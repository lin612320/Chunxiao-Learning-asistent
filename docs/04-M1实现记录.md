## 一、M1 交付内容

### 1.1 Rust 检索层（`src-tauri/`）

| 项 | 内容 |
| --- | --- |
| `db::material_search` | FTS5（trigram）BM25 优先 + **LIKE 兜底**；`course_id` 可选（`None` = 全库）；`limit` 默认 8 / 上限 50；空查询返回 `[]` |
| 返回行 | 9 个 snake_case 字段 `chunk_id / material_id / material / kind / seq / page / heading / snippet / score` |
| `score` 方向 | SQLite `bm25()` 越小越相关（负值）→ 取负号**统一成"越大越相关"**，避免调用方误解 |
| `snippet` | Rust 侧以关键词为中心裁切 ±100 字，**按 char_indices 换算字节边界，绝不断 UTF-8**；未用 SQLite `snippet()` |
| 命令 `material_search` | 参数 `{courseId?, query, limit?}`，返回数组 |
| 命令 `extract_material_b64` | 容忍 `data:...;base64,` 前缀 → 20 MB 上限 → 临时文件（保留原扩展名，office 按扩展名分派）→ 提取 → **成功失败都删临时文件**；与 `extract_material` 共用 `extract_to_value`，**返回形状逐字段一致** |
| 桥接闭环 | `action == "material_search"` → 全库检索 → 回写 `to-ball.json` 的冻结载荷 → **不再 emit `ball-push`**；取锁/检索失败只打日志 + 回一条带 `note` 的空结果（不让球面板干等 6 秒超时） |

## 二、集成阶段发现并修掉的 3 个问题（本轮最有价值的部分）

### 2.1 ⚠ 我在契约里写错的"查询词口径"（设计缺陷）

**问题**：契约初稿要求球侧"取选中文字**前 60 个字**作为查询词"。这在中英文混排的长选段上会失效：
含标点时 FTS 的 `MATCH` 会把它当成**多词短语**、`LIKE` 兜底路径又要求整段**字面**命中 ——
结果是**长选段几乎必然判"未命中"**，球面板会显示"未命中"，看起来像功能坏了。

**谁发现的**：Rust 实现代理在执行契约时识别出该缺陷，**没有擅自改冻结口径**，而是如实上报请主代理决策 —— 这个处理方式是对的。

**修法**：`ball.rs::pick_keyword` 改为**按标点/空白切段取词**：优先第一个 4–30 字的片段 → 退而取第一个 2–30 字的片段 → 整段无标点则截取开头 30 字窗口。
单测 `pick_keyword_extracts_a_searchable_segment_from_long_selection` 钉死四种情形（长选段取首分句、两字选段保留、以标点开头不带标点进查询词、无标点超长截窗）。

### 2.2 便携版多版本共存时会拉起**最旧**的包

`ball.rs::probe_dir` 的便携版分支用 `found.sort()`（**文件名字符串排序**）取首个。字符串排序会把
`春晓助手 1.0.10.exe` 排在 `春晓助手 1.0.2.exe` **之前** —— 升级后会拉起历史旧包。
而同一文件的 `sorted_subdirs` 对 `win-unpacked-*` 已经是"版本越大越优先"的口径，两处不一致。

**修法**：新增 `portable_ver()` 抽版本号数字序列，排序后取最后一个（最高版本）。
单测 `portable_ver_orders_by_version_not_by_string` 明确把"字符串排序是错的"钉在测试名里。

### 2.3 打包成品的**品牌缺陷**（T1/T10 一并关闭）

第一次打包（`signAndEditExecutable: false`，照抄母本）产出后我做了图标构成核对，发现：

| 产物 | 品牌化情况 |
| --- | --- |
| 便携版最外层 `春晓助手 1.0.1.exe` | ✅ 绿(品牌) 82% |
| **内层 `win-unpacked\春晓助手.exe`** | ❌ **暗色 73% = Electron 默认图标**，版本信息 `ProductName=Electron` |

根因：`signAndEditExecutable: false` 会**跳过 rcedit**，连带图标与版本信息都不写入；而**运行时的任务栏图标取自内层 exe**，所以这是用户可见的品牌缺陷。

**先试了打开该开关 → 打包失败**：`WinPackager.signApp` 需要 electron-builder 的 `winCodeSign` 包，
缓存里虽有 `rcedit-x64.exe`，但 electron-builder 25.1.8 期望的版本目录布局对不上（缓存是哈希命名），于是又去联网下载 → 被拦。
**这也解释了母本为什么把它设成 `false` —— 那是为本机网络环境打的绕行，不是配置疏忽。**

**最终修法（全程离线）**：用 electron-builder 的 **`afterPack` 钩子**自己调 rcedit。
`floating-ball/scripts/after-pack.js` 在「app 目录已打包完成、各 target 尚未生成」之间运行，
因此它改过的内层 exe **会被随后生成的便携版一并收进去**。
rcedit 从 electron-builder 缓存里按两种可能的目录命名探测，也支持 `RCEDIT_PATH` 显式指定；
**找不到 rcedit 时只告警不失败**（打包仍应成功，只是 exe 未品牌化）。

顺带把悬浮球版本递增为 **1.0.2**（母本经验：重打必须递增，否则旧常驻进程会顶掉新包），
并让 `make-icons.ps1` 额外产出 `floating-ball/assets/icon.ico`（rcedit 只吃 `.ico`，不吃 `.png`）。

**修后核对**：

| 产物 | 结果 |
| --- | --- |
| 内层 `win-unpacked\春晓助手.exe` | ✅ **绿 100%**、`ProductName=春晓助手`、`ProductVersion=1.0.2` |
| 便携版 `春晓助手 1.0.2.exe` | ✅ 绿 82%、`ProductName=春晓助手`、`ProductVersion=1.0.2` |
| 打包形态启动 | ✅ 进程存活、钩子进入自动抓取、stderr 空、退出无残留 |

同时把 `tauri.conf.json` 的 `bundle.resources` 补上（`../floating-ball/dist/win-unpacked` → `win-unpacked-0.1.0`），
并在 `plugins` 段留下"目录名必须随发版递增"的说明（母本连续踩过 `Error opening file for writing`）。

### 2.4 附带：把项目规范做成闸门自动拦截

`edit` 类工具写 `.ps1` 不带 BOM，而 Windows PowerShell 5.1 会把无 BOM 的 UTF-8 当 GBK 读，
导致含中文的脚本报出**与行内容无关**的解析错误。这个坑在本轮又出现了一次。

处理方式不是"每次记得手工补"，而是**把它加进质量闸门第 6 步**：`scripts/*.ps1` 必须带 UTF-8 BOM。
现在这类错误由闸门自动拦截。

## 五、M1 的诚实边界（对外口径务必一致）

- 材料检索是**关键词召回**（FTS5 BM25 + LIKE 兜底），**不是语义检索**；问题是"换个说法就搜不到"属预期行为。
- 材料导入的文本是**本地离线提取**（不过模型），pdf / 图片路径**明确标注"需配置支持视觉/文件输入的模型，M2 支持"**，不假装能解析。
- 会话里的引用来自**用户导入的原文**；AI 自己的补充**必须显式标注无出处**（前端已实现该区分）。
- 悬浮球的「材料」按钮现在**真的可用**了（M0 时它只到"写入请求"，并如实显示兜底提示）。
