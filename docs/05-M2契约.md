> **目标**：把 M1 留下的三个缺口补上 —— ① pdf/图片能真正解析（走视觉模型，标注「非原文」）；② 课程先验知识能 AI 生成（带来源标注与人工确认）；③ 检索从"单个关键词"升级到"多词召回 + 命中高亮"。
> **前置**：M0 + M1 已完成（质量闸门 6/6 · 单测 27/27 · 三个冒烟全绿）。
> **派生自**：[`00-可行性评估.md`](00-可行性评估.md) §6.4 / §7.3、[`01-M0骨架契约.md`](01-M0骨架契约.md) §四.1、[`03-M1材料导入与检索契约.md`](03-M1材料导入与检索契约.md)。

## 二、视觉模型转录（前端）

### 2.1 触发条件

课程页导入文件时，**先**走既有的 `extract_material_b64`（本地离线提取）：

- 若返回的 `text` 非空 → 行为不变，直接 `material_add`（`extracted_by: "local"`）。
- 若返回 `kind` 为 `pdf` / `image`（即 `text` 为空、`note` 说明需要视觉模型）：
  - **已配置 API Key** → 调视觉模型转录，成功后 `material_add`，且
    - `extracted_by: "model"`
    - `text` = 转录文本
    - `note` = `"模型解析，非原文"` （若转录失败，保留原 note 说明原因）
  - **未配置 Key** → 保持 M1 现状：如实提示「需配置支持视觉/文件输入的模型」，仍允许入库（`text` 为空 + note 记原因）。

### 2.2 调用方式

`src/lib/ai.ts` **已有** `ApiContentPart` / `ApiMsg`（含 `image_url` 与 `file` 两种块，注释写着"M2 启用"）。
新增一个**独立文件** `src/lib/vision.ts`（不要改 `chatStream`，它只做流式文本）：

```ts
export interface VisionResult { ok: boolean; text: string; err?: string }
export async function transcribeWithModel(
  cfg: AIConfig, fileName: string, base64: string, note?: string | null,
): Promise<VisionResult>
```

- 请求：`POST {normalizeEndpoint(cfg.baseUrl)}`，`stream: false`，`temperature: 0.1`，
  `messages: [{ role: "user", content: [ {type:"text", text: PROMPT}, <按 MIME 选 image_url 或 file> ] }]`
  - `image/*` → `{ type: "image_url", image_url: { url: "data:<mime>;base64,<b64>" } }`
  - `application/pdf` → `{ type: "file", file: { filename, file_data: "data:application/pdf;base64,<b64>" } }`
- `PROMPT`（**学习场景，与母本口径一致**）：
  > 你是课堂材料的转录助手。请完整提取这份材料的可学习内容：标题与章节层级、正文要点、公式与符号、图表说明、例题与解答。只输出材料本身可靠呈现的内容，不要评论、不要补全缺失信息；无法可靠辨识的部分明确标注「无法辨识」。
- 超时 180 秒；失败要把 HTTP 状态与平台可能不支持该输入的提示拼成**可读中文错误**（例如提示改用 gpt-4o / Qwen-VL 一类支持视觉的模型）。
- 返回文本上限 80,000 字（超出截断）。

### 2.3 诚实口径（**必须落实**）

- 转录文本是**模型解析、非原文**：`note` 必带「模型解析，非原文」，且**列表里要显式展示该标注**（M1 已有 note 展示位）。
- 导入汇总里要区分：`本地提取 n 个 / 模型解析 m 个 / 需要视觉模型但未配置 k 个`。

## 三、先验知识 AI 生成（前端）

### 3.1 入口与流程

课程详情页新增按钮 **「✨ AI 生成知识骨架」**：

1. **输入**：课程名（必填，来自课程行）+ 课程简介（有则带）+ 已导入材料的**文件名与 heading 列表**（作为弱提示，帮助模型贴合真实课程；**不要把材料全文塞进提示词**）。
2. **提示词要求**：输出**严格 JSON 数组**，每项 `{ "topic": string, "summary": string, "detail": string, "parent_topic": string | null }`；
   顶层为章节，`parent_topic` 指向所属章节以形成两级树；**禁止编造具体数据、条文、页码、引用**（只输出概念与关系）。
3. **解析容错**：容忍 ```json 代码围栏与前后废话；解析失败给出可读中文错误并**保留原始输出**供用户查看（不要静默失败）。
4. **必须预览**：生成结果以可勾选列表展示（topic / summary 可编辑，默认全选），用户点「确认入库」才写库。
   ⚠ **禁止"一键直接灌库"** —— AI 生成的先验知识未经核对就入库，违反产品红线（评估文档 §7.3）。
5. **入库**：对每一项调既有命令 `prior_add`：
   - `source: "ai"`（**必填字段，不可省略**）
   - `confidence: 0.5`
   - `sourceRef: "AI 生成 · 待核对"`
   - 不传 `verified`（默认 0 = 待核对，UI 已有「标记已核对」）
   - `parentId`：若该项 `parent_topic` 能匹配本次生成的某个 topic，则填对应已入库条目的 id；否则 `null`。
6. 已存在先验知识的课程再次生成时，**只追加**，不删除既有条目（删除是用户显式操作）。

### 3.2 未配置 Key 时

按钮禁用并提示去「数据设置」配置（**不要**用模板硬编码一份假知识骨架冒充 AI 生成）。

## 四、检索质量（Rust + 前端）

### 4.1 Rust：多关键词 OR 召回

改造 `db::material_search`，**对外签名与调用方式不变**。

**分词规则**（新增私有 `split_terms`）：

- 按空白与中英文标点切分（与 `ball.rs::pick_keyword` 的标点集合保持一致）；
- 去首尾空白、去空、**去重（大小写不敏感）**、只保留**长度 ≥ 2** 的词；
- **最多取前 8 个词**（防止超长查询）。

**检索策略**：

1. **FTS5 路径**：只用**长度 ≥ 3** 的词（trigram 分词器对 2 字词无法命中），拼成 `"w1" OR "w2"`（**每个词必须用双引号包裹**，否则词里的 `-` `*` `"` 等会被 FTS 当成语法 → 必须不报错）；若没有 ≥3 的词 → 跳过 FTS。
2. **LIKE 兜底路径**：用**全部词**（含 2 字词）OR 连接：`(content LIKE %w1% ESCAPE '\' OR heading LIKE %w1% ... OR content LIKE %w2% ...)`，`score` 固定 0，`ORDER BY material_id, seq`。
3. **FTS 命中 0 → LIKE 兜底**（保持 M1 行为）。
4. **单关键词查询的行为必须与 M1 完全一致**（回归：FTS 命中就返回、`score` 降序、2 字词走 LIKE）。
5. 空查询（trim 后无 ≥2 字词）→ 返回 `[]`。
6. `snippet`：在**任一关键词最早出现处**居中裁切 ±100 字（都没命中则取前 200 字）；仍不得切断 UTF-8 边界。

**返回行新增字段 `terms`**（其余 9 个字段名与类型**一律不变**）：

```json
{ "chunk_id":…, "material_id":…, "material":…, "kind":…, "seq":…, "page":…,
  "heading":…, "snippet":…, "score":…, "terms": ["梯度下降", "学习率"] }
```

`terms` = 本次实际使用的词列表（前端拿它做高亮）。

**必须新增的单测**：

| 测试 | 钉住的行为 |
| --- | --- |
| `material_search_multi_keyword_or_recall` | 造两块文本，各只含其中一个词；查询两个词（用空格/逗号分隔）必须**两块都召回**（只 AND 或只取首词的实现会红） |
| `material_search_survives_fts_syntax_chars` | 查询里含 `-` `*` `"` `(` 等 FTS 语法字符**不得报错**，仍能走 LIKE 兜底给结果 |
| `material_search_response_includes_terms` | 返回行含 `terms` 数组，且已去重、已去掉长度 <2 的词 |
| `split_terms_dedups_and_caps` | 去重（大小写不敏感）、丢弃 1 字词、最多 8 个 |

> **多词 OR 的作用范围（实现后补充说明）**：多词召回**只从对话页进入**。
> 悬浮球那条桥接路径会先经 `ball.rs::pick_keyword` 抽词（按标点取片段），
> 所以从球里发出的长选段最终是**单个词**，不会走到多词分支。
> 因此 `scripts/smoke-material-chain.ps1` 的第 2 轮覆盖的是 **pick_keyword 切段的端到端行为**
> （断言回传的查询词不含标点、且是原文子串），多词 OR 的正确性由上面的 Rust 单测覆盖 —— 两者不要混为一谈。

### 4.2 前端：命中高亮

- 用返回的 `terms` 在**材料片段（snippet）**与**引用来源列表**里高亮命中词。
- ⚠ **必须安全渲染**：材料内容与用户查询都可能含 HTML 字符 —— **禁止** `dangerouslySetInnerHTML` 或字符串拼 HTML。
  做法：把文本按命中词切成分段数组，用 React 元素渲染（命中段用 `<mark>` 包裹），并提供一个小工具函数（例如 `lib/highlight.tsx` 或 `lib/materials.ts` 内导出）。
- 高亮在**浏览器预览与桌面两种模式**下都要工作。

### 4.3 前端：按材料聚合（可选，能做则做）

引用来源列表可按 `material` 聚合展示（同一材料的多个片段折叠在一组下），并显示该材料命中数。做不到不影响验收。

## 六、约束

1. **不改已冻结项**：命令名、既有返回字段名与类型、`enc.` 前缀、桥接文件名与载荷、`material_add` 参数、路由结构、`styles.css` 设计令牌。
2. **不新增 npm / crate 依赖**（高亮用 React 元素渲染实现，不引库）。
3. **M0/M1 功能不得退化**：课程 CRUD、来源徽标、BYOK 引导、演示模式、`?float=1` 紧凑模式、材料导入与引用来源、悬浮球「材料」按钮。
4. **诚实边界**：模型转录标注「非原文」；AI 生成先验知识必须预览后由用户确认；未配 Key 时给可读提示而不是假装能用。
5. Windows：`cargo` 写 stderr 会被 PowerShell 当错误记录，**判成功看 `$LASTEXITCODE`**；含中文的 `.ps1` 必须带 UTF-8 BOM（已在质量闸门第 6 步自动拦截）。
