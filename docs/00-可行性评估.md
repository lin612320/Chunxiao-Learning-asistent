## 一、结论摘要

**可行性：高。** 母本与目标产品属于**同构应用**——都是「Tauri 2 桌面主程序 + 独立 Electron 悬浮球 + 本地 SQLite + OpenAI 兼容模型 + 手写 CSS 设计令牌」的本地优先架构。母本已经把这条技术路线上最难的工程问题解决完了（选区抓取、多窗口协同、透明置顶窗、文档提取、导出、打包踩坑），我们是用它的**已验证骨架**换新业务。

用户提出的 13 项预想功能，评估结论分布：

| 分布 | 数量 | 说明 |
| --- | --- | --- |
| ✅ 基本现成（照搬） | 7 项 | 悬浮球、抓取、AI 问答、会话存储、文档格式提取、番茄钟、桌宠容器 |
| ⚠ 小改即可 | 3 项 | 多模态图片粘贴、笔记导出（补 PDF）、先验知识生成 |
| 🔨 真正的新活 | 3 项 | **用户画像与"自我迭代"**、**笔记高亮批注**、**答题归因与自适应** |

**两条必须守住的红线**（详见 §7，这两条比技术选型更重要）：

1. **「自我迭代」不能说成"模型在自我迭代"。** 客户端拿正确率当奖励去"训练"模型是做不到的，能做的只有加权调整题库与提示词。母本在这一点上是教科书级克制——它的 0.8.0「联邦配方进化」方案稿页面明确写着"聚合/差分隐私/K 匿名是**真实实现**，客户端行为是**仿真**，**这不是强化学习**"，并因此**不计入"已实现"清单**。我们必须继承这个诚实标准。
2. **产品不能变成考试工具。** "任意界面划词即答 + 拍照提问"在考场上是作弊器。定位、文案、功能边界都必须在产品内写清（课后理解 / 复习 / 笔记），这是产品能否立住的问题，不是措辞问题。

## 二、母本同构性分析

### 2.1 架构对照

| 层 | 母本（法元 · Faron） | 春晓学习助手 | 复用度 |
| --- | --- | --- | --- |
| 桌面壳 | Tauri 2（Rust），49 个 `#[tauri::command]` | 同 | 骨架照搬 |

| 数据库 | SQLite（rusqlite 0.31 bundled），WAL，FTS5(trigram) | 同 | 换表 |
| 悬浮球 | Electron 33 独立应用，4 个窗口（球/面板/气泡/换肤） | 同 | **整套照搬** |
| 桥接 | `%APPDATA%\floating-ball\{from,to}-workbench.json` + Rust 侧 `ball.rs` | 同 | 照搬 |
| AI | OpenAI 兼容 `/chat/completions` 流式 + function calling | 同 | 换提示词与工具集 |
| 样式 | 手写 CSS + CSS 变量设计令牌 + 日/夜双主题 | 同 | 照搬令牌体系 |
| 打包 | NSIS，悬浮球装入**版本化目录** `win-unpacked-<ver>` | 同 | 照搬（含踩坑规则） |

**关键判断**：母本把"业务"与"框架"切得很干净——`src/` 是纯前端、`src-tauri/` 是命令层+数据层、`floating-ball/` 是自包含应用。所以**换业务不会伤及框架**，这是它最大的复用价值。

### 2.2 母本的"第二价值"：它的工程纪律

母本有三条做法值得整套继承，它们是为"AI 应用"量身定制的：

1. **确定性自检代替模型自述** —— 母本的文书质检不是问模型"你写对了吗"，而是用**代码规则**抽取正文里的条文号，逐一与工具真实返回的法条比对，未覆盖的点名提示。学习助手对应版本：**笔记/答案里的引用必须逐一核对出处**。
2. **工具只说真话** —— 智能体的工具（`laws_search` 等）只返回本地库真实条文，结果带 `refs` 可溯源，模型被强制"只引用真实返回"。学习助手对应版本：**课程问答只允许引用已导入材料与已核对先验知识**。
3. **诚实边界写进产品** —— 方案稿页面自己标注"不计入已实现清单"。这条文化必须继承（见 §7.2）。

### 3.3 白拿的 6 条踩坑经验（母本已付费）

这些坑母本在 CHANGELOG 里记了因由，直接照抄结论可省大量调试时间：

1. **覆盖安装报错** `Error opening file for writing` —— 悬浮球在安装包里的资源目录必须**随版本号递增**（母本 0.3.1/0.3.2/0.7.1 都踩过）。
2. **uiohook 只能 `start` 一次** —— 停止后再启动经常挂不回来，导致切回自动抓取时静默失效。正确做法：钩子常驻，只用 `armed` 布尔开关控制是否触发。
3. **窗口"越拖越大"** —— Aero Snap / 系统行为会改窗口尺寸。正确做法：`setMinimumSize = setMaximumSize = 固定值` + 800ms 尺寸看门狗。
4. **透明无边框窗口 Ctrl+C/V 失效** —— 必须显式注册编辑菜单（`buildEditMenu`）与 `before-input-event` 处理。
5. **拖动漂移** —— 位移必须按"起始位置 + 光标增量"计算，不能累计叠加，并钳制在 `workArea` 内。
6. **单实例锁 + 文件桥接** —— 第二个实例立即退出；跨进程命令走 `%APPDATA%` 控制文件轮询，而不是二次进程传参（打包 exe 的参数透传不可靠）。

## 四、DSH 内容搬运（决策 2 的细化）

### 4.1 结论：搬内容，不搬运行时

**为什么不能直接搬 DSH 插件进 Tauri/Electron 应用**（实读结论）：

DSH 插件 = `npm 包` + `package.json` 的 `dsh.bundle.patch` + `cordis.patch.yml` + 客户端 bundle，运行在 **cordis 依赖注入容器**里，靠 DSH 宿主注入服务（`dsh-llm`、`dsh-tools`、`dsh-session`、`dsh-client-ui-slots` 等）。实测形态：

- `dsh-pomodoro` = `cordis.patch.yml`（声明行）+ `lib/index.js`（441 B 加载器）+ `lib/client.js`（**13.8 KB React 组件，注册到 `conversation.session.header.actions` 插槽**）。剥掉 DSH 的 UI 插槽体系，它无处可挂。
- `maid-whale-webui` = 皮肤包（`skin.json` + WebP 美术 + CSS Module + 生成式 `*-art.generated.ts`，含 1.1 MB 的 `ornament-art.generated.ts`）。它的"桌宠"是**页面边缘吉祥物**，不是自由漂浮的桌面宠物；皮肤逻辑绑在 DSH Web UI 的 DOM 上。
- DSH 安装包（`D:\DSDeskTop\DSH Desktop\resources\app`）内含约 200 个 `@deepseek-ai/dsh-*` 包，其中 `dsh-headless` / `dsh-sdk-app` / `dsh-sdk-jsonrpc-server` / `dsh-sdk-protocol` / `dsh-acp` 存在——即**"把 DSH 当引擎侧车"技术上可行**，但那属于另一条路线（分发要带 Node 运行时、需要凭据、DSH 处于 rc 期 API 会变），与决策 2 不符，**本次不做**，留作 M4 之后的可选评估项。

### 4.3 ⚠ 许可证审查结论（重要，影响桌宠方案）

`maid-whale-webui` 为 **BSD-3-Clause**（Copyright (c) 2026, yunxi），但它的 `NOTICE` 文件把话说得很明白，**存在两处不可控的第三方权利**：

| 方案 | 可行性 | 建议 |

| 路由 | react-router-dom 6.26（HashRouter） | 适配 Tauri 文件协议 |

### 6.3 数据模型（SQLite DDL 草案）

```sql

CREATE TABLE IF NOT EXISTS courses (
  id          INTEGER PRIMARY KEY AUTOINCREMENT,
  name        TEXT NOT NULL,            -- 课程名称
  term        TEXT,                     -- 学期，如 2026-秋
  teacher     TEXT,
  intro       TEXT,                     -- 课程简介
  cover       TEXT,                     -- 封面图路径
  archived    INTEGER NOT NULL DEFAULT 0,
  created_at  TEXT NOT NULL

-- ② 先验知识（课程知识骨架）—— 每条必须带来源，这是 §7.3 的落地
CREATE TABLE IF NOT EXISTS course_prior (
  id          INTEGER PRIMARY KEY AUTOINCREMENT,
  course_id   INTEGER NOT NULL REFERENCES courses(id) ON DELETE CASCADE,
  parent_id   INTEGER,                  -- 树形：课程 → 章 → 节 → 知识点

  summary     TEXT,                     -- 一句话要点
  detail      TEXT,                     -- 详细说明（Markdown）
  source      TEXT NOT NULL,            -- ai | textbook | web | user | <材料名>
  source_ref  TEXT,                     -- 出处：页码 / URL / 材料 id

-- ③ 材料（课件 / 电子书 / 讲义）

  id          INTEGER PRIMARY KEY AUTOINCREMENT,

  file_name   TEXT NOT NULL,
  file_path   TEXT NOT NULL,

  size_bytes  INTEGER,
  extracted_by TEXT,                    -- local(本地离线提取) | model(视觉模型转录)
  text_len    INTEGER,
  truncated   INTEGER NOT NULL DEFAULT 0,
  note        TEXT,                     -- 「模型解析，非原文」等免责标注

CREATE TABLE IF NOT EXISTS material_chunks (
  id          INTEGER PRIMARY KEY AUTOINCREMENT,
  material_id INTEGER NOT NULL REFERENCES materials(id) ON DELETE CASCADE,
  course_id   INTEGER NOT NULL,
  seq         INTEGER NOT NULL,         -- 块序号，用于回原文定位
  page        INTEGER,                  -- 页码（可定位则填）
  heading     TEXT,                     -- 所属标题路径
  content     TEXT NOT NULL,
  tokens      INTEGER
);
CREATE INDEX IF NOT EXISTS idx_chunk_material ON material_chunks(material_id, seq);

-- ⑤ 全文检索（FTS5 优先；trigram 分词，中文友好）
CREATE VIRTUAL TABLE IF NOT EXISTS chunks_fts USING fts5(
  content, heading, content='material_chunks', content_rowid='id', tokenize='trigram'
);
-- 触发器三件套（母本 db.rs 同款：ai / ad / au）负责与 material_chunks 同步

-- ⑥ 对话（照搬母本 chat_sessions / chat_messages）
```

### 6.4 检索策略：先 FTS5，别一上来上向量库

母本在 15.3 万条法库上得到的明确结论：**不适合一次性全量 embedding，走的是"关键词召回 → Top-K 喂模型"**，且 FTS5 用 **trigram 分词**（中文友好）+ BM25，异常时静默回退 `LIKE`。

学习助手的对应策略：

1. **教材/课件** → 切块入库 → **FTS5 召回** → Top-K 喂模型（k 建议 5–8，块长 500–800 字）。
2. **向量检索作为增强而非底座**：仅对"已核对过的先验知识 + 笔记"做小规模向量化（几千条量级），用于语义模糊查询；`mem_vectors` 表与 `embed.ts` 母本已就绪。
3. **硬约束**：模型回答里的每一条引用都要能指回 `material_chunks.id` 或 `course_prior.id`，指不回就标注"无出处的模型补充"（§7.3）。

## 七、产品红线与诚实边界

> 这一章比技术选型重要。母本用"诚实边界"换来了可信度，我们必须继承。

### 7.1 考试红线（产品能否立住的前提）

"任意界面划词即答 + 拍照提问"在考场上是作弊器。**必须**：

- 产品定位与首屏文案写明适用场景：**课后理解 / 复习 / 笔记整理 / 答疑**，不面向考试场景。
- 不做"答案速出"式设计：把"给答案"改成"追问到你讲清楚"（§8.1 第 2 项），从机制上区别于作弊工具。
- 悬浮球面板不提供"一键提交/一键抄"路径。

### 7.2 "自我迭代"的口径（最容易被戳穿的一条）

客户端**做不到**用正确率训练模型。能做的只有：

| 真实做得到的 | 做不到的（不许宣称） |
| --- | --- |
| 用正确率/偏好**加权**题库选题与复习优先级 | 策略梯度、价值函数、长程信用分配 |
| 用弱项**调整提示词与解释粒度** | "模型在自我进化/自我迭代" |
| 用历史记录做**间隔重复**排程 | "越用越聪明"（模型权重没变） |
| 记录并展示**掌握度变化**（纯统计） | 联邦学习 / 云端聚合模型 |

**落地要求**：产品内（画像页 / 关于页 / 对外文案）必须区分**「真实实现」**与**「协议仿真」**，并明确写出"这不是强化学习"。母本在 0.8.0 方案稿页面就是这么写的，并因此把它排除在"已实现"清单外。

### 7.3 AI 生成知识的溯源（母本"不编造"思路的平移）

- `course_prior.source` 为**必填**：`ai` / `textbook` / `web` / `user` / 材料名。
- AI 生成条目**默认低置信 + `verified = 0`**，界面用视觉区分，并提供"一键纠正"。
- 问答回答中的每条引用必须可回链；**无出处的模型补充必须显式标注**。
- 可平移母本的**确定性自检**：代码规则抽取回答中提到的知识点/页码，与检索结果逐一比对，未覆盖的点名提示——不依赖模型自述。

### 7.4 材料版权（母本经验**不适用**的地方）

母本敢内置 467 MB 法库，因为来源是 e-Gov / govinfo / constitutioncenter **公开数据**。电子书与课件**不适用**：

- 只允许"用户导入自用"，**绝不随安装包分发**，**绝不回传云端**（与决策 1、3 一致）。
- 首次导入时一次性提示"请确保你有权使用该材料"。
- 演示站/宣传材料里不出现任何受版权保护的教材内容。

### 7.5 BYOK 的体验兜底（决策 3 的配套）

BYOK 上手有门槛，必须把摩擦降到最低：

- 首启引导一屏搞定：**平台预设下拉**（DeepSeek / OpenAI / 通义 / 智谱 / 自定义）→ 粘贴 Key → 一键测试（母本有 `ai:testKey` 调 `/models` 的现成实现）→ 保存。
- 平移母本两个细节：**平台域名自动纠错**（用户常粘控制台网页地址）与**重复粘贴 Key 自动去重**。
- `enc.` 前缀混淆落盘（母本 `keycrypt.js` + Rust `keycrypt.rs` 对称实现）。
- 无 Key 时进入**演示模式**（母本做法：预设流水线 + 真实工具执行），保证软件不"开箱即死"。

### 8.1 建议加（按性价比排序）
