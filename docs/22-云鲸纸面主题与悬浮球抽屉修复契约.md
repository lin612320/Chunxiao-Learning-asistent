## 五、真缺陷：悬浮球设置抽屉「文字重叠」

### 5.1 根因

抽屉原来是 `.app` flex 列的**第三个兄弟**（`top` / `body` / `drawer`）：

```css
.drawer { max-height:60%; overflow:auto; flex:0 0 auto; }   /* 会吃掉最多 60% 高 */
.body   { flex:1 1 auto; min-height:0; }                    /* 可以被压到比内容还矮 */
/* .body 的子项却全是 flex:0 0 auto 且各有 min-height（结果区 44px / 两个框 / 按钮行） */
```
抽屉一开，`.body` 被压到小于自身内容高度，而它的子项**不收缩** →
**子项直接溢出到 `.body` 之外，压在抽屉上** —— 用户看到的就是"文字叠字"。

### 5.2 修法

抽屉改成**覆盖层**（`position:absolute; left/right:0; top:38px; bottom:0; z-index:30; overflow:auto`），
**不再与 `.body` 争同一段高度**；同时把抽屉底色做成**不透明**（`--drawer-bg`），
否则底下的输入框会透上来、看着仍像叠字。另补 `.row { min-width:0 }` / `.row input{min-width:0}` 防横向溢出。

### 5.3 为什么之前没有一层抓到它（这一轮最该记住的）

面板版面守门（R5.1 建的，42 条）只测**主界面那六个控件**：
两个输入框、两个按钮、两个抓取模式按钮 —— **从来没打开过抽屉**。
所以"抽屉里的文字叠了"在 8 层验证里**没有任何一层会红**（与 0.7.0「收起」卡死是同一类：
验证覆盖的是"我以为用户会看的地方"）。

**处置**：版面守门从 **42 → 50** 条，新增 8 条专测抽屉：
① 抽屉能打开且有内容；② **每一行都完整落在窗口内**；③ **行与行不重叠**；
④ **抽屉不压到内容框**（就是"叠字"那条）。两个尺寸（360×460 / 420×620）各一遍。

**并且验证它能红**：把抽屉的旧 CSS 还原到一份临时副本上跑 ——
**PASS 47 / FAIL 3**，其中一条正是：
```
[FAIL] 抽屉不压到内容框（文字不叠字） —
  抽屉首行={y:195.2..232.2} 内容框={y:201.6..256.6}   ← 实测重叠 37px
```

## 七、本轮踩到的坑

**PowerShell 5.1 的 `Set-Content -Encoding UTF8` 会写 BOM**，而 `floating-ball/package.json`
是被 `electron-builder` 直接 `JSON.parse` 的 → 报
`readObjectStart: expect { or n, but found , error found in #1 byte`，
`signtool` 之前的打包步骤直接失败。同一批改的 `package.json` / `Cargo.toml` / `tauri.conf.json`
也被写了 BOM（vite/tauri 恰好容忍，所以只有球的构建暴露出来）。

**规矩**：改这些配置文件一律用
`[System.IO.File]::WriteAllText($path, $text, (New-Object System.Text.UTF8Encoding($false)))`，
写完 `node -e "require('./package.json')"` 复验一次。
