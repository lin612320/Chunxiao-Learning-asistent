## 一、口径红线（比功能更重要）

1. **归属是用户的显式选择，不是模型的推断**：界面必须**始终可见**当前课程上下文；不允许"看着像 A 课、实际按全库检索"。
2. **检索范围必须与界面所写一致**：`scopeText` 写什么，`material_search` 就必须按什么查（有课程上下文→只搜该课程；无→全库，且文案照旧写明"本机全库"）。
3. **不静默套用"最近使用的课程"**：`/assistant` 无参数时**就是**不限定课程。最近课程只用于：① 课程页入口显式带入；② 阶段 2 悬浮球；③ 界面给一条**可选的**提示条，绝不自动改变检索范围。
4. **提炼出的先验知识不自动入库**：必须**生成 → 预览（可勾选、可编辑）→ 点「确认入库」才写库**（沿用 M2 已冻结的预览确认管线）。
5. **素材含 AI 自己的回答，必须声明**：提示词里必须显式告知"对话中的【春晓】回答也是 AI 生成的、**未经核实**"，并要求：禁止编造、把不确定的内容**显式标注**、不得把 AI 的说法写成事实。
6. **截断必须如实告知**：素材按字符预算从**最新往前**纳入；界面必须写明"本次用了 n 条（共 m 条，已截断为最近的 k 条）"。
7. **无记录不生成**：该课程没有问答记录时如实提示，**不造数据、不用模板冒充 AI**。

## 二、后端新增命令（Rust）

**命令数 67 → 70**。**零 DDL 变更**：`chat_sessions.course_id` 建表即存在，且 `db.rs:389` 的 `ensure_column` 已保证旧库平滑升级。

### 2.1 `chat_session_set_course`

| 参数 | 返回 |
| --- | --- |
| `id: i64`、`courseId: Option<i64>` | `()` |

- `courseId = null` → 把会话置为**不限定课程**（写 `NULL`）。
- **不改 `updated_at`**：该字段语义是"最后消息时间"、用于列表排序；改归属不是消息事件。
- 幂等（重复设同一值无副作用）。
- 校验：会话不存在 → 「会话不存在（id=N）」；`courseId` 非空但课程不存在 → 「课程不存在（id=N），请先在「课程」页创建。」

### 2.2 `chat_course_messages`

| 参数 | 返回 |
| --- | --- |
| `courseId: i64`、`since: Option<String>`（`YYYY-MM-DD`，含当日）、`limit: Option<i64>` | `Value` |

```
{
  "session_count": 3,                 // 该课程会话总数（含无消息的）
  "session_count_with_messages": 2,   // 其中至少有一条可选消息的（**与 available_count 同口径：同样受 since 过滤**）
  "message_count": 57,                // 本次实际返回的消息条数
  "available_count": 120,             // 满足 since 条件的总条数（未截断前的）
  "truncated": false,                 // message_count < available_count 时为 true
  "messages": [
    {"session_id": 1, "session_title": "…", "role": "user", "content": "…", "created_at": "…"}
  ]
}
```

- **只返回** `role != 'system'` 且 `content` 非空的消息。
- 排序：`ORDER BY m.created_at, m.id`（升序）。
- `since`：按 `substr(created_at,1,10) >= since` 过滤。
- `limit`：**默认 2000、上限 5000**；**取最近的**（先倒序截断再翻正序），避免长会话把最新内容截掉；`truncated` 如实置位。
- `session_count_with_messages` **与 `available_count` 同口径**（同样受 `since` 过滤）：这样 `available_count = 0` 时它必为 0，两个数字不会互相打架。*（口径由实现代理提出、架构师采纳，在此定死。）*
- 无会话 → `session_count: 0, messages: []`（**不返回 null**）。
- **存在理由**：① 提炼先验知识只需 **1 次 IPC**；② 顺手关闭 **T20**（"收集当天消息是 N 次 IPC"）。

### 2.3 `prior_add_tree`

| 参数 | 返回 |
| --- | --- |
| `courseId: i64`、`items: Array`、`source: String`、`sourceRef: Option<String>`、`confidence: Option<f64>` | `Vec<i64>`（与 `items` 顺序一一对应） |

- `items` 元素字段用 **snake_case 且与 `PriorDraft` 逐字一致**：`{topic, summary?, detail?, parent_topic?}`。
  > 理由：契约 §四.1 的 camelCase 口径针对**顶层命令参数**；嵌套载荷跟随"草稿结构"可让前端**零字段转换**，少一类低级错误。此处显式登记。
- **父子解析在 Rust 侧完成**（1 次 IPC）：先插顶层项（`parent_topic` 为 `null`），再插子项并按 `parent_topic` **逐字**映射到本批某个顶层项的 id。
- `source` **必填且非空**（沿用 `prior_add` 红线：「没有来源的知识点不允许入库」）；`verified` 硬编码 `0`（与 `prior_add` 一致）。
- **事务**：整批在同一事务内；任一项非法 → **全部回滚**并给可读中文错误（不留半截数据）。
- 校验：`topic` 非空且 ≤200 字；子项的 `parent_topic` 必须**逐字命中**本批某个顶层 `topic`，否则报「父知识点「X」不在本批中」；`source` 为空 → 报错。
- **存在理由**：与 M4 的 `questions_save_batch` 同一教训（"避免前端 N 次 IPC（M3 已因此留下 T20 的教训）"）。
- **本轮只被提炼流程使用**：M2 的 AI 生成入库管线（`Course.tsx:418-471` 的逐条 `prior_add`）**本轮不改**，以免回归已验证路径；列为后续机会。

## 三、前端

### 3.1 课程上下文与路由

- `/assistant?course=<id>` = 该课程上下文；`/assistant`（无参数）= **不限定课程**。
- **保留** `?float=1`（既有冻结行为，虽然当前无调用方 —— 见 §五 第 1 条）。
- `localStorage` 键 `chunxiao:last-course-id`：记录用户**最近一次显式选择**的课程上下文（课程页入口或对话页选择器）。沿用既有 `localStorage` 偏好约定（`chunxiao:focus` / `chunxiao:notes-export-dir`），**零新表、零新命令**。

### 3.2 对话页（`Assistant.tsx` + `useChat.ts`）

- 顶部新增**课程选择器**：`不限定课程` + 课程列表（当前课程即使已归档也要能显示出来）。
- 切换课程 → 更新 URL（`?course=N`）并写入 `chunxiao:last-course-id`；切换后会话列表按新上下文重筛，自动选中该上下文最近一个会话；该上下文无会话时保持既有文案「还没有会话，直接提问会自动新建一个」。
- `useChat({ courseId })` 接上 URL 参数（**这是 G1/G2/G3 的修复点**）。
- **改归属**：当前会话显示归属，并提供选择器（`不限定课程` + 课程列表）→ `chat_session_set_course`。
  - 改成功后**跟随切换上下文**（navigate 到新归属的 URL），并给出明说提示：「已把会话「X」移到《Y》」/「已把会话「X」改为不限定课程」。
- **检索范围文案**：`scopeText` 改为"当前会话归属优先、其次 URL 上下文"；两者都没有时**必须**仍然写明「检索范围：全部课程材料（本机全库）」（既有诚实口径，不弱化）。
- `/assistant` 无参数时，若 `chunxiao:last-course-id` 有值 → 显示一条**可选**提示条「上次你在《X》学习，切到该课程？」+ 一键切过去；**不自动改变**检索范围（§一 第 3 条）。

### 3.3 课程页（`Course.tsx`）

- 新增「**与该课程对话**」按钮 → `/assistant?course=<id>`，同时写 `chunxiao:last-course-id`。
- 挂载新组件「**从本课对话提炼先验知识**」（§3.4）。

### 3.4 从本课对话提炼先验知识（新组件）

- 新文件 `src/components/PriorFromChatCard.tsx` + `PriorFromChat.css`（自带样式，复用既有设计令牌；**不引图表库、不新增依赖**）。
- 新文件 `src/lib/priorfromchat.ts`（提示词 + 素材构建 + 口径常量），**复用 `priorgen.ts` 已导出的 `parsePriorJson` 与 `PriorDraft`**，不重复实现解析。
- 流程：
  1. 未配 Key → 按钮**禁用**并引导去「数据设置」（既有口径）。
  2. 调 `chat_course_messages(courseId)`；无消息 → 如实提示「这门课还没有问答记录，先去对话页问几个问题」。
  3. 素材构建：按**字符预算**（`PRIOR_FROM_CHAT_BUDGET = 24000` 字符）从**最新往前**纳入消息；界面写明实际用了多少条、是否截断（§一 第 6 条）。
  4. 提示词要求**严格 JSON 数组**（两级树，与 M2 同构：顶层=章节，子项用 `parent_topic` 指向章节），并**逐字包含**对 AI 回答的免责声明与"禁止编造数据/条文/页码/引用"。
  5. 解析（容忍 ```json 围栏与前后废话，复用 `parsePriorJson`）→ **可勾选可编辑预览**。
  6. 「确认入库」→ `prior_add_tree(courseId, items, "ai", "从对话提炼 · 待核对", 0.4)`。
- **入库口径（已拍板）**：`source="ai"`、`source_ref="从对话提炼 · 待核对"`、`confidence=0.4`（**低于** M2 纯生成的 `0.5`，因为素材含 AI 回答）、`verified=0`（由 `prior_add_tree` 硬编码）。
  > **不新增 `source` 枚举值**，以免改 `docs/00` §7.3 冻结的 `source` 取值集合；区分只体现在 `source_ref` 上。
- 入库后明说：「已写入 n 条，标记为『从对话提炼 · 待核对』，请逐条核对」。

### 3.5 关闭 T20

- `notes.ts::collectDayMessages` 从"列会话 + 逐个 `chat_history_load`（1+N 次 IPC）"改为 **`chat_sessions_list`（1 次，取会话总数与标题）+ `chat_course_messages`（1 次，一次拿全）**，就地按日期过滤。
