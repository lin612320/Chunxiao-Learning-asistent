## 〇、先说结论（可行性评估）

| 问题 | 结论 | 依据 |
| --- | --- | --- |
| 手写笔记能不能在**现有架构**里做出来 | **能，且零数据库改动** | 手写笔记就是 `notes` 表里的一条普通笔记（`source='ink'`），正文 = 逐页 PNG + 笔迹围栏 |
| 触控笔压感 / 倾斜能不能拿到 | **能**（浏览器标准 Pointer Events） | `pointerType === 'pen'` + `pressure` + `tiltX/tiltY`；拿不到时**如实退化成等宽**，不假装有 |
| 需不需要引第三方墨迹库 | **不需要** | 引擎全部自写（`src/lib/ink.ts`，零依赖），项目「不新增第三方依赖」的约定没有被第二次破例 |
| 平板能不能用（界面上） | **能** | 窄屏侧栏改抽屉 + 触控目标 ≥40px，桌面端界面**逐像素不变**（媒体查询只在小屏生效） |
| 手写识别（转文字）能不能做 | **能，但必须联网** | 走用户自己的视觉模型（BYOK）；Web 层**没有**可用的离线中文手写识别，界面上如实标注「模型转写 · 非原文」 |
| Android / iPadOS 打包能不能做 | **未核实** | 本机有 Rust 1.98 + Android SDK/NDK 27、28 + Android Studio 的 JBR，但 `rustup` **未安装** android 目标，也没有 `src-tauri/gen/android`；iOS 必须在 macOS + Xcode 上做 |

**一句话**：手写这条线**技术上没有拦路虎**，风险全部集中在"要不要真的出一个平板安装包"，
而那件事与本期的代码实现是**解耦**的（前端代码在浏览器 / Windows 桌面 / 移动 WebView 上是同一份）。

## 一、决策基线（已拍板）

| # | 决策项 | 结论 | 代价 / 理由 |
| --- | --- | --- | --- |
| 1 | 交付形态 | **不另做一套移动端页面**，只做外壳适配 | 代价：窄屏的信息密度不如原生；理由：另开一套会让此后每个需求都写两遍 |
| 2 | 手写落库方式 | **复用 `notes` 表**（`source='ink'`） | 代价：正文带 base64，`content_len` 不是"字数"；收益：备份/还原/列表/导出/悬浮球桥接全白拿 |
| 3 | 墨迹真源 | 正文里的 ` ```chunxiao-ink ` 围栏（紧凑 JSON） | PNG 只用于**显示**；真源是笔迹数据，所以能重新编辑（橡皮 / 撤销 / 改色都还在） |
| 4 | 显示与导出 | 笔迹**光栅化成 PNG**（dataURL） | `lib/markdown.tsx` 刻意排除 `image/svg+xml`（脚本注入面），所以不能存 SVG |
| 5 | 手写识别 | 只走 BYOK 视觉模型，**不内建离线识别** | Web 层没有可用的离线中文手写识别；假装有比没有更糟 |
| 6 | 防误触 | 规则式：**笔一出现就忽略所有 touch**（+2.5s 保护期） | 浏览器不给手掌压力数据，阈值式判定会误伤"用笔时用手指挪纸" |

## 二、触控笔输入：技术约束（写清楚"我们能拿到什么"）

| 能力 | 来源 | 拿不到时的行为 |
| --- | --- | --- |
| 压感 `pressure` (0–1) | `PointerEvent.pressure` | 非笔（鼠标/手指）**固定 0.5**；笔恒报 0.5 时笔迹等宽 —— 界面「笔自检」可当场看出 |
| 倾斜 `tiltX/tiltY` | `PointerEvent.tiltX/tiltY`（度） | 恒报 0/0；界面如实标注"这支笔不报倾斜" |
| 接触面积 `width/height` | `PointerEvent.width/height` | 仅用于**自检显示**与手掌启发式，不参与绘制（与压感相关性太弱） |
| 高采样率合并事件 | `getCoalescedEvents()` | 不支持时退回"每次事件一个点"（120Hz 的笔会被降帧）——「笔自检」里会明说 |
| 笔尖悬停 | `pointerType==='pen'` 且 `pressure===0` | 悬停**不落点**，只更新位置（不做悬停重绘：会吃光帧率） |
| 手掌压力 / 手掌标识 | **浏览器不提供** | 走 §一/6 的规则式防误触 |

**笔迹预测刻意不做**（`getPredictedEvents`）：预测点必须在真实点到达后**回退重画**，
没做这套补偿就用预测，会出现"笔尖后面拖着一条会缩回去的尾巴"，比不加预测更糟。

## 三、数据格式（`notes.content_md` 的结构）

```markdown
# 标题

![手写 · 第 1 页](data:image/png;base64,…)

<!-- 以下为手写笔迹的原始数据，供再次编辑；请勿手动修改 -->
```chunxiao-ink
{"v":1,"pages":[{"paper":"grid","w":1240,"h":1754,"bg":"data:image/png;base64,…",
  "strokes":[{"t":"n","c":"#1f2328","s":3,"p":[x,y,p, x,y,p, …],"b":1,"g":"★"}]}]}
```
```

| 字段 | 含义 | 备注 |
| --- | --- | --- |
| `t` | 工具代号：`n` 钢笔 / `c` 铅笔 / `m` 荧光笔 / `l` 直线 / `k` 标注符号 | 橡皮与框选**没有代号**（它们不产生笔迹） |
| `c` / `s` | 颜色 / 基准线宽 | 实际线宽 = `widthAt(工具, 线宽, 压感)`，再量化到 0.5px |
| `p` | **平铺三元组** `x,y,p` | 对象数组每点 ~30 字节，三元组 ~14 字节；一页几万点就是 1.2MB 与 560KB 的差别 |
| `b` | `1` = 画在**底层** | 荧光高亮带专用：盖在字上面就不是高亮，是涂黑 |
| `g` | 标注符号本身（≤4 字符） | 只能在 `zh` 之外……即只在 `t === 'k'` 时有意义；解析时超过 4 字符一律丢弃 |

**为什么围栏在渲染时"看不见"**：`lib/markdown.tsx` 把 ` ```chunxiao- ` 前缀的围栏当作
**应用内部数据块** —— 渲染为空、纯文本贡献 0 个字符。后者是硬要求：
块内纯文本偏移是批注锚点的尺子（`docs/07` §三），渲染侧不产生文本，纯文本侧就**必须**同样为 0，
否则批注高亮会整体错位。

**解析红线**：`parseDoc()` 遇到任何一处不合法就返回 `null`（调用方**必须如实告诉用户"读不出来"**），
绝不返回一个半截的、看起来能用的文档。底图字段只接受 `data:image/(png|jpeg|webp|gif);base64,…`。

## 四、工具集（这一期交付的"配套工具"）

| 工具 | 交互 | 实现要点 |
| --- | --- | --- |
| 钢笔 / 铅笔 | 笔迹，压感变宽 | 铅笔有**确定性抖动**（由点下标驱动，不是随机数 —— 否则撤销后红屏会看到笔迹在抖） |
| 直线 | 拖出两端 | 两点确定一条；短于 6 页面像素当误触丢掉；预览走 rAF 节流 |
| 荧光笔 | 半透明 + `multiply` 叠加 | 不随压力变宽（色带要均匀） |
| **标注符号** | 选符号 → 点一下盖一个 | 22 个常用符号（✓ ✗ ★ ☆ ※ ！ ？ ① ② ③ → ← ↑ ↓ ⇒ ⚠ + − = △ □ ○）；字号跟粗细滑杆（×6） |
| 橡皮 | 拖动连续擦 | **删点 + 断笔**（不是画白线）；一次拖动 = **一条**撤销记录；只重画受影响区域 |
| **框选** | 拖框选中笔迹 | 判定用外接框相交（slack 6px）；**手指也能用**（没有笔的平板照样要能选） |
| 框选 → 高亮 | 一键 | 在选中笔迹**下面**铺一条荧光色带（抽稀到 ≤60 点，线宽 ×4 夹在 8–60）；可叠加、可撤销 |
| 框选 → 变色 / 移动 / 删除 | 一键 / 拖动 / Delete | 移动是"逐笔平移 + 重建对象"（原对象不动，撤销栈才能还原）；染色保留工具/线宽/符号/层序 |
| 撤销 / 重做 | 按钮 + Ctrl+Z/Y | **操作栈**（数组浅拷贝），上限 100 步；撤销/重做会作废选区（下标会变） |
| 纸面 | 空白 / 方格 / 横线 / 点阵 | 与笔迹**分开**存储，换纸面不进撤销栈的"笔迹"分支，而是自己的 op |
| 多页 | 加页 / 删页 / 翻页 | 最后一页不许删；每页可有独立底图 |
| 缩放 / 平移 | 双指捏合 / 单指拖动 / 滚轮 / 按钮 | 以双指中点为锚点缩放；范围 0.2×–4× |
| 底图 | 选图铺在当前页下 | contain 铺满（不拉伸变形）；**不进撤销栈**（换底图是"换纸"）；随笔迹一起进 `content_md` |
| 导出 PNG | 当前页 2400px 长边 | 与屏幕视角**无关**（按页面原始比例重渲染，不是截图） |
| 打印 / PDF | 逐页输出 | 临时把每页 `<img>` 塞进 DOM 再打印；`body.hw-printing` 只输出打印容器 |
| **识别为文字** | 逐页交给视觉模型 | 结果进「文字稿」面板（可展开/复制/清空），保存时写进笔记的 `## 文字稿（模型转写，非原文）` |
| 笔自检 | 展开面板 | 显示来源/压感/倾斜/接触面积，以及"本环境是否支持合并事件" |

## 五、诚实边界（**不要在界面上暗示已经做到**）

1. **手写识别不是离线能力**：必须配 API Key、会联网、会花 token，结果是模型转写**非原文**；
2. **不做笔迹预测**（理由见 §二）；
3. **压感不校准**：S Pen 与 Apple Pencil 的原始曲线不同，同一条笔迹在两台设备上粗细感受不同；
4. **画圆不会变成正圆、画线不会自动拉直**（除"直线"工具外无形状吸附）——页脚已明写这一条；
5. **`docx` 导出里看不到手写页**：`src-tauri/src/docx.rs` 目前**不处理图片**，
   而手写页是内联 PNG。`.md` 导出是完整的（PNG 就在 Markdown 里）。**这是本期未解决的缺口**；
6. **`source='ink'` 需要后端白名单**：`db.rs` 的 `NOTE_SOURCES` 已同步加 `ink`，
   两处漏改会表现为"保存报『来源只能是…』"（这是白名单故意为之的**如实失败**）；
7. 手写笔记在**笔记列表**里不显示"N 字"（`content_len` 是图片与笔迹数据的字符数，显示出来是误导），
   改显示「手写」徽标 + 「触控笔」标签。
