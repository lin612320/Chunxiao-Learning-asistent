# M1 · 材料导入与带出处检索（契约）

> **目标（评估文档 §11.2 的"技术风险归零"判定）**：导入一份 PDF/课件 → 切块入库 → **FTS5 检索** → 模型**带出处**回答，且出处可回链到具体材料与片段。
> **前置**：M0 已完成（质量闸门 5/5 · 桌面冒烟 8/8 · 桥接冒烟 10/10 · 单测 20/20）。
> **本文冻结 M1 的接口**，前后端并行开发以此为准。派生自 `00-可行性评估.md` §6.4 与 `01-M0骨架契约.md` §三/§四.1。

---

## 一、M1 只做三件事（严格限定范围）

| # | 事项 | 说明 |
| --- | --- | --- |
| 1 | **材料导入** | 课程页可导入 docx / pptx / xlsx / xls / txt / md / csv（**本地离线提取，不过模型**）；pdf 与图片走"需视觉模型"的诚实提示（M2 再做） |
| 2 | **带出处检索** | 新增 FTS5 检索命令：在**已导入材料的切块**里按关键词召回，命中片段带材料名与标题路径 |
| 3 | **带出处回答 + 桥接闭环** | 对话页新增「就课程材料提问」：先检索 Top-K → 把编号来源喂给模型 → 回答下方列出引用来源并落库；**同时让悬浮球面板的「材料」按钮真正可用**（M0 留的桥接链路接上主程序检索） |

**明确不做**（留给后续里程碑）：向量检索、图片 OCR/视觉模型解析、自动生成先验知识、笔记、题库、画像。

## 二、新增的 2 个 Tauri 命令

### 2.1 `material_search`

| 项 | 值 |
| --- | --- |
| 参数 | `courseId: Option<i64>`（**省略或 null = 全库检索**，供悬浮球无课程上下文时用）、`query: String`、`limit: Option<i64>`（默认 8，上限 50） |
| 返回 | `Vec<Value>`，**按相关度降序**；无命中返回 `[]`（不返回 null） |

返回行字段（**snake_case，与其它命令一致**）：

```json
{
  "chunk_id": 12,
  "material_id": 3,
  "material": "第3章 极限与连续.pdf",
  "kind": "pdf",
  "seq": 12,
  "page": null,
  "heading": "3.2 极限的运算法则",
  "snippet": "……命中片段（约 200 字，居中裁切到关键词附近）……",
  "score": 1.23
}
```

**检索策略（照抄母本在 15 万条法库上验证过的两条结论）**：

1. **FTS5 优先**：`chunks_fts`（trigram 分词）用 BM25 打分；`MATCH` 命中后按 `material_chunks.course_id` 过滤（`courseId` 为 Some 时）。
2. **必须保留 LIKE 兜底**：trigram 分词器对 **< 3 字的查询无法命中**（中文两字词很常见）；且 FTS 不可用/语法异常时**不得报错**，静默回退 `LIKE '%kw%'`（对 `content` 与 `heading`），score 给固定值 0。
3. **空查询直接返回 `[]`**（不返回全量）。
4. `snippet` 由 Rust 侧裁切（关键词附近 ±100 字），不要整块返回。
5. `score`：FTS 路径用 BM25（越小越相关的话请取负号，**统一成"越大越相关"**，避免调用方误解）。

### 2.2 `extract_material_b64`

| 项 | 值 |
| --- | --- |
| 参数 | `fileName: String`、`dataB64: String` |
| 返回 | `{kind, text, blocks, truncated, note}`（与既有 `extract_material` **形状完全一致**） |
| 用途 | 前端 `<input type="file">` 只能拿到**字节**、拿不到绝对路径；由 Rust 写临时文件 → 复用 `office::extract_office_text` → 删除临时文件 |
| 约束 | 大小上限 **20 MB**（超出返回可读中文错误）；`dataB64` 需容忍 `data:...;base64,` 前缀 |

## 三、桥接闭环（让悬浮球的「材料」按钮真正可用）

M0 里悬浮球的「材料」按钮已经打通到写桥接文件（`action: "material_search"`）并如实显示"M2 开放"的兜底提示。M1 把主程序这一侧接上。

**主程序 → 球**的回传载荷（**逐字冻结**，球侧 `panel.js` 已按此解析）：

```json
{
  "ts": 1790000000000,
  "cmd": "material_result",
  "kw": "极限",
  "results": [
    { "material": "第3章 极限与连续.pdf", "page": null, "snippet": "……" }
  ],
  "note": "可选：无命中时的说明"
}
```

实现点：
- 在 `ball.rs::start_bridge_poller` 读取 `from-ball.json` 后，若 `action == "material_search"`：**调 `db::material_search(conn, None, text, Some(8))`（全库）** → 通过 `to-ball.json` 回传上述载荷 → **不再** `emit("ball-push")`（避免前端把它当划词文本）。
- 轮询线程已持有 `AppHandle`，用 `app.state::<DbState>()` 取库；取锁失败不要让线程 panic（打日志即可）。

> **⚠ 修正（2026-09-22，实现阶段发现并改）**：本条原写"取前 60 个字作为查询词"，**该口径有缺陷**——
> 中文长选段含标点时，FTS 的 `MATCH` 会把它当成多词短语、`LIKE` 兜底路径又要求整段**字面**命中，
> 导致**长选段几乎必然判"未命中"**（球面板会显示"未命中"，看起来像功能坏了）。
> 现改为按中英文标点/空白**切段取词**：优先第一个 4–30 字的片段 → 退而取第一个 2–30 字的片段 →
> 整段无标点则截取开头 30 字窗口。实现见 `ball.rs::pick_keyword`，并由单测
> `pick_keyword_extracts_a_searchable_segment_from_long_selection` 钉死（含"以标点开头不带标点进查询词""两字选段保留""无标点超长截窗"三种情形）。

## 四、前端接线

### 4.1 课程页「材料」标签页（替换 M0 的"M1 开放"）

- **导入入口**：`<input type="file" accept=".pdf,.docx,.pptx,.xlsx,.xls,.txt,.md,.csv,.png,.jpg,.jpeg,.webp">`（多选）。
  - 流程：读文件为 base64 → `extract_material_b64(fileName, dataB64)` → `material_add(courseId, fileName, "", kind, sizeBytes, "local", text, blocks, truncated, note)`。
  - `file_path` 传**空字符串**（字节导入没有真实路径）；此时列表里**不显示**"在文件夹中打开"按钮。若将来走原生拖拽拿到真实路径，再传真实路径。
  - 导入过程中显示进度（第 i/n 个），逐个处理，**单个失败不中断整批**，最后汇总"成功 n / 失败 m"与每条失败原因。
  - `extract_material_b64` 返回 `note` 非空（pdf/图片）时，**如实提示**"本格式需要配置支持视觉/文件输入的模型，M2 开放"，但仍允许入库（`text` 为空、`note` 记录原因）。
- **列表增强**：显示 `kind` 徽标、`chunk_count`（已切块数）、`text_len`、`extracted_by`、`truncated` 标记、`note` 提示。

### 4.2 对话页「就课程材料提问」

- 输入区加一个开关（默认开启）：**「📚 先查课程材料再回答」**。
- 开启时的流程：
  1. 用用户问题调 `material_search(courseId, question, 8)`；
  2. 构造编号来源块注入系统提示词：
     ```
     你可以引用下面这些来自用户课程材料的片段。只引用真实片段，不要编造。
     若片段不足以回答，请明确说"材料中未找到相关内容"。
     【1】（第3章 极限与连续.pdf · 3.2 极限的运算法则）
     <片段内容>
     【2】……
     ```
  3. 走原有流式对话；
  4. **回答下方渲染「引用来源」列表**（材料名 · 标题路径 · 片段摘要），可折叠；
  5. 把来源以 `refs` 字段持久化到该条消息（`chat_history_save` 已支持 `refs` / `source_kind`，**不要**改 Rust）。
- 检索无命中时：**如实**在回答里注入"未在你的课程材料中找到相关内容"，并仍允许模型用自身知识回答，但要在 UI 上标注该回答**无材料出处**。
- 该开关的检索范围跟随当前会话所属课程；无课程上下文（全局对话）时传 `courseId: null`（全库）。

### 4.3 数据的诚实口径（沿用 M0 纪律）

- AI 回答中来自材料的引用必须能回链；**无出处的模型补充必须显式标注**。
- 材料片段是**用户导入的原文**，与"AI 生成"区分开；不要在 UI 上把检索命中的材料片段说成 AI 分析结果。

## 六、约束与注意事项

1. **不要改已冻结的东西**：命令命名、行字段 snake_case、`enc.` 前缀、桥接文件名 `from-ball.json`/`to-ball.json`、`material_add` 的既有参数。
2. **M0 的验证不能退化**：改完必须复跑各自验收；`scripts/verify-m0.ps1` 必须仍全绿。
3. **不新增依赖**（前后端都不加 npm/crate 依赖）。
4. Windows 环境：含中文的 `.ps1` 必须带 UTF-8 BOM（M0 记录 §3.3 已说明）；`cargo` 写 stderr 会被 PowerShell 当错误记录，**判断成功请看 `$LASTEXITCODE` 而不是管道退出码**。
5. 前端已有的浏览器预览降级路径（`!isTauri()` → `data/sample.ts`）要同步扩展：`material_search` 在预览模式下返回示例数据，保证 UI 可脱离 Rust 调试。
