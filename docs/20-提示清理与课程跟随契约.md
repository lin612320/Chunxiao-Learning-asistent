## 二、真缺陷：顶部切课程后，各功能页的课程不跟着变

### 2.1 根因（读代码定位，不是猜）

R6 定下的「课程上下文」只有一处：**URL 的 `?course=N`**（侧栏选择器 + 顶栏胶囊 + 各页链接同源）。
但四个页面里只有两个真的读它：

| 页面 | R9 之前 | 结果 |
| --- | --- | --- |
| 笔记 `Notes.tsx` | `parseCourseParam(search)` → `lockedCourseId` ✅ | 跟着切 |
| 对话 `Assistant.tsx` | `parseCourseParam(search)` → `effectiveScope` ✅ | 跟着切 |
| 题库 `Questions.tsx` | ❌ 自己的 `useState(courseId)` + 「课程加载完兜底第一门」 | **恒为第一门课** |
| 画像 `useProfile.ts` | ❌ 同上（自己的 state + 兜底第一门） | **恒为第一门课** |

所以「顶栏写着《计算机系统基础》、题库/画像还在统计《数据库系统》」不是偶发，是这两页**压根没看 URL**。

### 2.2 修法：与笔记页同一个口径

- `?course=N` 存在 → **锁定**它（`Questions.tsx` 的 effect 直接 `setCourseId(urlCourseId)`；
  `useProfile(lockedCourseId)` 新增入参，锁定态下**禁止**"兜底第一门"覆盖它）；
- 没有 `?course=N` → 保持页内自选（原行为不变）；
- 锁定态下**隐藏页内的课程选择器**（与笔记页一致）—— 当前范围由侧栏 + 顶栏负责，避免三处重复，
  也避免"页内选 A、URL 是 B"这种自相矛盾的中间态。

## 三、笔记：按天整理 + 软件内预览

- **按天分组**：列表按 `notes.date` 分组，**日期倒序**（最近的在前）；
  **没有日期**的（老数据 / 手动写没填日期）归到最后的「未标日期」组 —— **不猜日期**。
- **两种来源混排**：自己写的（`source='user'`）与 AI 从对话整理的（`source='ai_session'`）
  **在同一组里**，靠来源徽标（「自己写的」/「AI 整理 · 待核对」）区分 ——
  用户要的是"按天看笔记"，不是"按来源分两个列表"。
- **软件内预览**：点列表任意一条 → 右侧渲染 Markdown 正文（`lib/markdown.tsx`）+ 批注层 + 导出按钮；
  AI 生成的**草稿在保存前就有预览**（原有能力，未改）。本轮把列表改成按天后，两种来源的入口完全一致。
- 新增 CSS：`.notes-day` / `.notes-day-head` / `.notes-day-label` / `.notes-day-count`（`Notes.css`）。

## 四、一键核对

### 4.1 新命令 `prior_verify_all`

| 项 | 内容 |
| --- | --- |
| 形状 | `prior_verify_all(courseId) -> i64`（返回受影响的条数） |
| SQL | `UPDATE course_prior SET verified = 1 WHERE course_id = ?1 AND verified = 0` |
| 为什么一个命令 | 前端循环调 `prior_verify` N 次 = **N 次 IPC + N 次事务**（T20 记过的教训），中途失败还会留下"一半核对过"的中间态。这里**一条 UPDATE、一次事务** |
| ⚠ 只动 `verified` | **不碰** topic / summary / detail / source / source_ref / confidence —— 「核对」是**用户的确认动作**，不等于系统改写内容（`verified` 只由用户确认，不由系统自证） |
| ⚠ `WHERE` 必带 `course_id` | 否则"一键"会变成**越权批改别的课** |

### 4.2 前端

- 按钮出现在「先验知识」区标题旁：**「一键核对（N 条）」**；`N === 0` 时**不摆一个灰按钮**。
- 点之前先 `window.confirm`，并写明**会一次标掉多少条**、以及**只改"是否已核对"这一个标记** ——
  这是用户自己的确认动作，必须让他知道自己在确认什么。
- 完成后如实提示「已把 N 条标为「已核对」。」（不谎报条数）。
- 预览模式：直接改 `localStorage` 里的示例库，行为与桌面版一致。
