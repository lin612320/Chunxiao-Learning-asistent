## 一、先说一个**必须先解决的前提**（这是本轮的核心发现）

「点材料打开」听起来是一行前端代码的事，**但在这个项目里做不到** —— 因为：

1. 材料的正文是按**字节**导入的：前端用 `<input type=file>` 拿到 `File` → `readFileAsB64` →
   `extract_material_b64`。**浏览器不给出文件的绝对路径**。
2. 所以 `views/Course.tsx` 里 `material_add` 的 `filePath` **一直被硬编码成空字符串**，
   并附着一行注释：「字节导入没有真实路径（M1 契约 §4.1）」。
3. 而 `open_file`（Rust，早就有）**需要一个真实存在的路径**才能交给系统默认程序打开。

也就是说：**库里所有材料的 `file_path` 都是空的**，「点开就打开」无从谈起。
`open_file` 这个命令从 M0 建起来之后**从来没有被前端调用过** —— 它是一个没人用的能力。

**所以本轮真正要做的是：让材料有原文件可开。** 做法是导入时**在本机留一份副本**。

## 三、留副本：落盘位置、命名与代价

### 3.1 位置与命名

```
%APPDATA%\com.chunxiao.study\materials\<原名主干>__<内容指纹8位>.<原扩展名>
```

- **指纹**（FNV-1a 32 位，零依赖，自写在 `fingerprint8`）解决一个真实问题：
  多个课程里都有「课件.pdf」是常态，**同名不同内容不能互相覆盖**；而**同内容重复导入**又
  不该占两份 —— 指纹同时满足这两条。已由单测 `store_material_bytes_names_fingerprints_and_reuses`
  在临时目录里验证（同内容复用、同名不同内容另存、原副本不被覆盖）。
- **保留原名主干与扩展名**（扩展名统一小写）：用户自己翻这个目录时还认得出来，
  不至于看到一堆 UUID。

### 3.2 ⚠ 代价（如实登记）

**材料会在本机多占一份磁盘**（单文件上限 20 MB）。这是为"点开就能打开"付的明确代价，
不是遗漏。换来的是：**用户把原文件移走、改名甚至删掉之后，春晓这边照样能打开。**

### 3.3 为什么是"留副本"而不是"记原路径"

记原路径看似更省磁盘，但 `<input type=file>` 拿不到路径（见 §一），
而 Tauri 的窗口级拖放虽然能给真实路径，但本项目的导入入口是"点按钮选文件"。
留副本是唯一**对用户可靠**的做法（不依赖原文件一直待在原地）。

## 四、老材料怎么办：不摆假按钮，给「补存原文件」

**你库里现有的材料 `file_path` 全都是空的**（§一），所以：

| 情况 | 界面表现 |
| --- | --- |
| 有原文件位置（R13 之后导入的） | 摆 **「打开」**（系统默认程序）+ **「在文件夹中显示」** |
| **没有**原文件位置（R13 之前的） | **不摆「打开」**（摆了也是点了没反应），改为摆 **「补存原文件」** + 一行明说：**「只导入过内容，没有原文件位置」** |

「补存原文件」= 让用户重新选一次那个文件 → `material_store_file` 落一份副本 →
`material_set_path` 把路径记进库 → 以后就能打开。

> 口径说明：**补路径只改 `file_path` 一列**，`material_set_path` 的注释与单测
> （`material_set_path_only_touches_file_path`）都明确要求它**不许碰正文、切块与来源标注** ——
> 这是"补个位置"，不是"重新导入"。界面上的「模型转写 · 非原文」标注也因此原样保留。

## 五、实现细节里值得记下的四处

### 5.1 浏览器预览模式下必须**如实报错**

`open_file` / `material_store_file` 都是仅桌面版可用的动作。浏览器预览下前端会抛出
「该操作仅桌面版可用」，材料页把它显示在错误条里 —— **断言的就是这条"如实说做不到"**，
不是"假装打开成功"（`smoke-ui.mjs` 的 `预览模式下点「打开」如实报错`）。

### 5.2 校验逻辑抽出来共用（避免两处漂移）

`extract_material_b64` 与 `material_store_file` 都要「去 `data:` 前缀 → 清空白 → 长度上限 →
base64 解码 → 空/超限拒绝 / 文件名清洗」。原来这套逻辑写在 `extract_material_b64` 里，
本轮抽成 `decode_import_bytes` / `safe_file_name` 两个函数**共用**：

- 两处各写一遍，迟早会漂移成"提取能过、存副本被拒"这种怪事；
- 重构后 `extract_material_b64` 的**文案与行为逐字未变** ——
  既有的单测 `extract_material_b64_decodes_and_matches_extract_material_shape` 仍然通过，
  这就是"没有偷改行为"的证据。

### 5.3 `OK_EXT` 补 `pptx`：口径不自洽的地方

打开文件的白名单原来有 `docx/doc/md/txt/xlsx/xls/pdf/html/htm/csv/png/jpg/jpeg/webp`，
**没有 `pptx`** —— 而应用**本来就能导入 pptx**（`IMPORT_ACCEPT` 与 `office.rs` 都支持）。
结果是"导得进来、点开却说不支持"。本轮补上。

### 5.4 命令的参数名走既有约定

Rust 形参 `file_name` / `data_b64` / `file_path`，前端传 `fileName` / `dataB64` / `filePath`
—— 与既有 `extract_material_b64` 同一套（Tauri v2 的 camelCase→snake_case 映射）。
三个都是**非 `Option` 的必填 String**：名字写错会**直接报错**，不会像 `Option` 那样静默变 `None`。

## 六、验证（实测）

### 6.1 已跑

| 项 | 结果 |
| --- | --- |
| `npx tsc --noEmit` | **exit 0** |
| `npx vite build` | **exit 0 · 0 warning** |
| `cargo check` | **exit 0 · error=0 warning=0** |
| **Rust 单测** | **70 / 70**（67 → 70，新增 3） |
| **浏览器层 UI 冒烟** | **132 / 132**（124 → 132，新增 8） |

新增的 **3 条 Rust 单测**：

1. `material_store_helpers_sanitize_and_validate` —— 文件名清洗（`..\..\windows\…` 必须被剥成文件名，
   **不许让前端传来的名字变成路径**）、指纹稳定性、非法 base64 被拒、`data:` 前缀容忍。
2. `store_material_bytes_names_fingerprints_and_reuses` —— **真的写盘**：命名保原名主干 + 小写扩展名 +
   带指纹；同内容复用同一份；同名不同内容另存且**不覆盖**原有副本。（跑在临时目录，
   不碰用户 AppData。）
3. `material_set_path_only_touches_file_path` —— 补路径只动 `file_path`，
   `extracted_by` 与 `material_text_all` 结果**逐字不变**；不存在的 id → 报错不静默。

新增的 **8 条浏览器层断言**：侧栏有「相关材料」入口 / 点入口进得去 / 不带课程参数时按课程分组（≥2 组）/
锁定课程后不串课 / 有原文件位置的材料摆「打开」/ **没有原文件位置的摆「补存原文件」而不是「打开」** /
**没有原文件位置时如实写明原因** / 预览模式下点「打开」如实报错。

> 为了覆盖"没有原文件位置"这条诚实分支，`data/sample.ts` 特意加了一条
> `file_path: ""` 的示例材料（`机房上机指导.txt`）—— **样例数据里没有这条，
> 那个分支在浏览器层就永远走不到**。

### 6.2 负例 / 断言自查

- 本轮**发现并修掉了一条自己的坏断言**：「不带课程参数时按课程分组」原来写成依赖上一步的
  残留状态（R12 段落刚建了一门课并选中它），于是实际落到 `?course=<新课>`、分组数为 0 → 红。
  **改成自己显式导航到不带参数的模式**。这是"断言依赖别人留下的状态就会随机红"的又一例。
- 真机层新增的 5 条断言**挂在隔离自检通过之后**：其中「空库时如实说还没有材料」
  只有在隔离出来的空库上才成立，拿真实库跑必红 —— 断言依赖的前提，就得待在为它准备的分支里。

### 6.3 ⚠ 未跑：真机层那 5 条（如实登记）

`scripts/smoke-desktop-ui.mjs` 新增了 5 条真机断言（侧栏入口 / 材料页在真机下能开 /
空库诚实态 / 两个新命令的**拒绝路径**），但它们**本轮没有执行** ——
该脚本要求主程序**未在运行**（它要移开你的真实数据库），而跑的时候你正开着春晓。

所以下面这条**仍然没有自动化证据**：

> **「在真机上导入一个文件 → 副本真的落盘 → 路径真的写进库」这条端到端链路。**
> 它需要一次真实导入（走系统文件选择框），无法在 CDP 里自动化。
> 目前它被拆成两半分别验证：**落盘与命名**由 Rust 单测覆盖，
> **命令注册与参数名**由编译期 + 真机断言（待跑）覆盖。

想补跑真机层：**先关掉春晓**，然后 `powershell -File scripts/smoke-desktop-ui.ps1`。
