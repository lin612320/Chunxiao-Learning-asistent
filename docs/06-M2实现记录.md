## 二、集成阶段发现并修掉的问题

> M2 的两个实现代理各自完成了自己的部分，但**没有人走完"企业级用户实际怎么用"这条路**。下面 1、2、3 是集成阶段（主代理）实测/读码发现的。

### 2.1 ⚠⚠ 旗舰功能缺陷：中文提问几乎必然检不到材料

**怎么发现的**：Rust 代理交付并如实上报了一个"需要裁决"的召回问题后，我去核实前端**到底拿什么当查询词** —— 读到 `useChat.ts` 的调用点是 `materialSearch(searchCourse, content, 8)`，`content` 是**用户原句**。

**根因链**：

```
"梯度下降的学习率怎么选？"
  → split_terms 按标点切分 → ["梯度下降的学习率怎么选"]   ← 中文书写没有空格，整句变成一个 11 字词
  → FTS5 trigram 要整短语命中 → 0 命中
  → LIKE 要整句字面命中        → 0 命中
  → 结果 []  → 引用来源永远为空
```

**影响**：M1/M2 的旗舰卖点「先查课程材料再回答」在**最常见的输入形态下完全失效**，而用户只会看到"材料中未找到相关内容"。

**修法**：提问前抽内容关键词（`extractSearchTerms`）—— 标点切段 → 剥中文疑问/功能词 → 长连写片段再切 → 保原大小写去重 → 最多 3 个 → 优先长词；**抽词为空时退回整句并如实提示**。并把「本轮检索词」显示给用户，使"为什么没引用到"可理解。

**实测输出**（前端代理 node 实跑）：

| 输入 | 输出 |
| --- | --- |
| `梯度下降的学习率怎么选？` | `["梯度下降","学习率"]` |
| `什么是红黑树` | `["红黑树"]` |
| `为什么` | `["为什么"]` + **走整句兜底** |
| `时间复杂度 和 空间复杂度 的区别` | `["时间复杂度","空间复杂度"]` |
| `CNN 和 RNN 的区别` | `["CNN","RNN"]`（大小写保留） |

### 2.2 召回漏洞：混合长度多词查询静默丢块（代理上报 → 我裁决修）

Rust 代理如实上报：`"极限 梯度下降"` 时 FTS 只拿 ≥3 字词去查，一旦命中就不再走 LIKE，于是**只命中 2 字词「极限」的块被静默丢掉**。它明确说明这与契约 §4.1 第 3 条冲突、**没有擅自改**，请我裁决 —— 处理方式正确。

**裁决：必须修**。中文 2 字词（极限/导数/矩阵/概率）极常见，这是**召回漏洞**而不是可选优化。

**修法**：把"仅 FTS 0 命中才走 LIKE"改为"**FTS 没占满 limit 就用 LIKE 补齐未覆盖的块**"（FTS 命中按相关度在前，补齐的按 `material_id/seq` 追加在后，按 `chunk_id` 去重）。

**测试设计**（关键）：除了断言"两块都被召回"，还加了一条**机制反证** —— `limit=1` 时 FTS 占满名额、不再补齐、只回 FTS 命中。这既覆盖了"占满即停"分支，也**正好复现了修复前的行为**，因此该断言在旧逻辑下必然失败（测试具备敏感性）。

### 2.3 snippet 定位大小写敏感（读码发现）

FTS 的匹配不区分大小写，而 `snippet_around` 用的是大小写敏感的 `str::find` —— 查询 `CNN` 命中 `cnn` 时**定位失败**，片段退成"前 200 字"窗口：**用户看到的片段里根本没有命中词**，前端高亮也就无从下手（两个功能一起哑掉）。

**修法**：`find_ci` —— 按 ASCII 大小写折叠做字面扫描（不动中文，避免 `to_lowercase()` 改变字符数导致下标错位）。测试把命中点放在 250 字之后：若定位失败退回开头窗口就**不会**包含命中词，因此断言在旧实现下必然失败。

### 2.4 一个我先怀疑、读码后自己否掉的"问题"（并转成不变量测试）

我担心 FTS ∪ LIKE 合并会让**同一次响应里不同行的 `terms` 不一致**（FTS 路径的 MATCH 只用了 ≥3 字词，若把过滤后的词表回传，前端高亮会忽多忽少）。读代码确认 `search_fts` 传给 `build_hit` 的是**完整词表**，两条路径一致 —— 担心不成立。既然确认了，就把它写成断言（同响应各行 `terms` 必须相同且等于全量词表），让前端高亮的依赖被长期守住。

### 2.5 我抓到前端代理的"当前状态是红的"

在代理报告之前，我独立跑了一次只读类型检查（`npx tsc --noEmit`，不写 `dist/` 以避免与它的构建互扰）：

```
src/views/Assistant.tsx(9,1): error TS6133: 'Highlight' is declared but its value is never read.
```

`Highlight` 已导入但**未接线**（引用来源高亮这一环缺失），而代理的硬性验收是 `tsc exit 0`。我把这个精确信号推给它并要求"不要在 exit≠0 的情况下报完成"。**这是"子代理自报完成"与"独立复核"的差别** —— 只看报告就可能漏掉。

### 2.6 我独立审查了两处最高风险点（结论：做对了）

| 审查点 | 结论 |
| --- | --- |
| `highlight.tsx` 是否安全渲染 | ✅ 用 `m[0]` **原样渲染命中片段**（`CNN` 不会被显示成 `cnn`）；无 `dangerouslySetInnerHTML`、无 HTML 拼接；`normalizeTerms` **长词排前**（避免短词把长词切碎）并丢弃空词（避免正则空分支导致零长匹配） |
| `extractSearchTerms` 是否踩我警告的坑 | ✅ 保留原大小写；停用词正则按**长度降序**编译（避免"什么的"被"什么"先吃掉）；纯英文长词不切、中文长片段按 4 字窗切；暴露 `fallback` 供 UI 如实提示 |

### 2.7 我修的第三类问题：测试声明与实测不符

我扩展材料链冒烟时先写了"第 2 轮验证多词 OR 路径"，随后意识到**这是错的**：悬浮球那条桥接路径会先经 `pick_keyword` 抽词，**在桥上发多段文字根本到不了多词分支**（多词 OR 只从对话页进入）。于是改写为它**真正覆盖**的东西，并让断言可证伪：

```
→ {"text":"极限，导数；连续","action":"material_search"}
← {"cmd":"material_result","kw":"极限", …}
[PASS] 查询词不含标点（切段生效）
[PASS] 查询词是原文片段
```

这使 `pick_keyword` 的切段从"只有单测覆盖"变成**端到端验证**，同时把作用范围写进契约文档，避免以后把两条测试混为一谈。

## 五、M2 的诚实边界（对外口径务必一致）

- **模型转录是"非原文"**：pdf / 图片经模型解析的文本仅供参考，界面显式标注；**不做本地 OCR**。
- **AI 生成的先验知识未经核对**：一律 `source="ai"` + 「AI 生成 · 待核对」+ 待核对状态；**生成结果不自动入库**，必须用户预览后点「确认入库」，再逐条点「标记已核对」。
- **检索是关键词召回，不是语义检索**：换一种说法可能检不到；页面会如实展示本轮用了哪些检索词、是否走了整句兜底。
- **未配 Key 时不给假结果**：视觉转录与知识骨架生成在未配 Key 时会给出可读提示（知识骨架按钮直接禁用），**不用硬编码内容冒充 AI 生成**。

[FAIL] 无 4xx/5xx 资源请求 — 404 http://localhost:1420/favicon.ico
```

应用**根本没有 favicon** —— 于是**每次页面加载都产生一个 404**，标签页也没有品牌标。**其它四层验证全都抓不到它**（这正好说明这一层不是重复投入）。

**修法（可复跑）**：`scripts/make-icons.ps1` 增加产出 `public/favicon.ico` 与 `public/favicon-32.png`（vite 会把 `public/` 原样拷进 `dist/`），`index.html` 补 `<link rel="icon">`；质量闸门第 4 步同时校验这两个文件存在（否则下次换图标又会漏）。修后 UI 冒烟 **32/32**、无 4xx。

### 6.3 修工具自身：测试脚本必须先"能被诊断"

第一次跑 UI 冒烟时脚本自己崩了，两个坑都写进注释以免再犯：

1. **Edge/Chrome 111+ 的 `/json/new` 只接受 PUT**：用 GET 会返回 `Using unsafe HTTP verb GET to invoke /json/new`，随后 JSON 解析报错，现象与"Edge 起不来"很像。
2. **不能直接 `process.exit()`**：那时 WebSocket 仍处于关闭中，Node 触发 `Assertion failed: !(handle->flags & UV_HANDLE_CLOSING)`，进程以退出码 `0xC0000409` 异常终止，**把真实结论吞掉**。改为统一 `finish(code)`：先关掉所有 WS、等一拍、再退出。
3. 另修一处**可诊断性**缺陷：起初只报"有个 404"却不报**是哪个 URL**，无法定位；改为从 `Network.responseReceived` 记录具体 URL 后再断言。
4. 临时文件卫生：脚本初版在 `%TEMP%` 下留下 **10 个 Edge profile 目录与日志**（Edge 退出后文件句柄释放有延迟，一次 `Remove-Item` 会被 `-ErrorAction SilentlyContinue` 静默跳过）。改为**带重试的清理**，并统一为"**成功时自清临时文件、失败时保留日志**"（三个既有冒烟脚本也一并照此处理）。现在连续跑两次 UI 冒烟，断言均 32/32，`%TEMP%` 残留为 **0**，端口 1420 自动释放。

### 6.4 产物一致性：重打安装包

favicon 修复发生在打完 0.2.0 安装包**之后**，那个安装包因此**落后于源码**。按项目自己的规则（质量检查未过禁止打包、产物必须与源码一致），在 **7 步闸门全绿**后重打安装包，新值记入 §3.4。
