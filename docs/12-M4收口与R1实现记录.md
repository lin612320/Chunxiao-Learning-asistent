## 二、集成阶段发现并修掉的问题

### 2.1 一条红的守门单测：实现是对的，测试写错了

`db::tests::mastery_requires_min_evidence` 原本 panic 在 `db.rs:4958`「没作答的知识点也是样本不足」。

**根因**：`let ov = profile_overview(...)` 是**建点之前**取的快照，而断言用的知识点在之后才创建 → 拿旧快照去断言新知识点，**必红**。
**依据**：同文件 `profile_trait_set_rejects_mastery_and_upserts` **通过**且明确断言 0 作答知识点落在 `not_enough`；`question_stats` 是 `FROM knowledge_points WHERE course_id = ?1` 全量返回 → 实现行为自洽，错的只是取样时机。修法是**重取一次快照**，并在断言处留注释防后人误"修"实现。
> 这是**同类问题第二次**出现（M3 的 `db.rs:3337` 也是一模一样的"实现对、测试错"）。契约把这条称为「口径红线的守门测试」，它红着本身就是不该发生的状态。

### 2.2 一处口径歧义：`session_count_with_messages` 是否受 `since` 过滤

契约只写"其中至少有一条可选消息的"，没写是否与 `since` 同口径。实现代理选择了**与 `available_count` 同口径**（同样受 `since` 过滤），理由是保证 `available_count = 0` 时它必为 0、两个数字不互相打架。**架构师采纳并已在契约 §2.2 定死**。

### 2.3 「子项降级为顶层」只在入库**之后**才告知（口径问题）

实现代理原本只在入库成功的提示里说明"其中 N 条…已作为顶层条目写入"。问题：用户在点「确认入库」**之前**并不知道保存下来的结构会和预览不同 —— 违反契约 §一 第 4 条「不静默改变用户看到的内容」。

**已修正**：预览区（按钮之前）就显示警告，列出受影响条目名（超 16 字截断、最多 5 个 + 「等 N 条」），并复用与入库**同一个** `buildPriorAddTreeItems`（预览警告与实际写库数据必然同源）。顺带修掉一个真实文案 bug（「入库时会被**被跳过**」双「被」）。

### 2.4 ⚠ 我自己的验证事故：**测试数据写进了用户的真实数据库**

这一条必须完整记下来，因为它是本轮最严重的问题，且**完全是我的错**。

**发生了什么**

1. 我新建了「真机桌面 UI 冒烟」，为"不碰用户真实库"设计了隔离：把子进程的 `APPDATA` 指向临时目录。**这个假设是错的** —— Windows 的 known-folder API（`SHGetKnownFolderPath`）**不读 `%APPDATA%` 环境变量**，主程序照样打开了用户真实库。
2. 我的冒烟脚本又假设"空库 = 未配 Key = 演示模式"。而用户真实库里**配了真实 API Key**，于是脚本不只是写库，还**真的调用了用户的模型 API（产生了费用）**。
3. 白天还发生过一次更隐蔽的污染：在 4 个实现代理并行编辑期间我干跑了一次真机冒烟，vite HMR 把**半成品**前端喂给主程序，导致 `useChat` 当时仍忽略 `courseId`，于是脚本的测试问答被**追加进了用户原有的会话 1**。
4. 同一批断言里还有 3 条是**假通过**：新增的「课程上下文栏」复用了 `.session-bar` 类名，`document.querySelector('.session-bar')` 抓到的是选择器栏而不是会话列表栏 —— 于是"切到不存在的课程后会话消失"在**压根没有会话**时也"通过"了。

**实际影响**

- 真实库多出 **1 个会话 + 2 条消息**（真机跑出来的），以及**追加进用户会话 1 的 2 条消息**（干跑）。
- **1 次真实的模型 API 调用**（用户的 Key，用户付费）。
- 用户会话 1 中既有 4 条消息的 `created_at` 被**统一重写**为同一时刻 —— 这一步**不可恢复**（原因见 §四 T23：`chat_history_save` 结构性丢弃逐条时间戳）。

**我做的清理与证据**

| 步骤 | 证据 |
| --- | --- |
| 一致性备份 | `sqlite3 .backup` → `%TEMP%\chunxiao-db-backup-before-r1-cleanup.db`（139,264 B，含污染前状态，保留未删） |
| 精确定位污染行 | 会话 `id=2 / course_id=1 / 标题 R1冒烟课程归属…`；消息 `id=12,13` 属会话 1 |
| 精确删除 | 只删这些行（**先按 ASCII 的 `id` 条件**：中文常量经 PowerShell 传给 `sqlite3` 会编码不匹配，`LIKE 'R1冒烟%'` 曾静默不匹配 → 这条坑也记下） |
| 空间回收 | `VACUUM` + `PRAGMA wal_checkpoint(TRUNCATE)` |
| 终检 | SQL 层：`sessions=1 / messages=4 / courses=1`、`integrity_check=ok`、含标记行数 `0`；**字节层**：主库+WAL 中标记命中 `0` |
| 还原 | 用户会话 1 恢复为其原有 4 条消息；真实库目录无 `.smoke-bak` 残留 |

> 说明：`VACUUM` 是对用户库的一次维护性写入（重写文件以清掉 free page 里的残留字节）。除此之外我没有改动、删除或重排用户的任何数据。

**根因修复（脚本侧）**

1. **隔离改为"移开真实库（`*.smoke-bak`）+ 用完还原"**（与 `smoke-desktop.ps1` 同一套做法）：不依赖任何环境变量假设，路径相同就一定隔离得住。文件头用醒目注释写明"**这里踩过真实事故，别再改回去**"。
2. **主程序在跑时拒绝执行**（`exit 2`）：库文件正被占用，强移有风险。
3. **隔离自检**：断言必须处于"空库无 Key ⇒ 演示模式"，自检不通过就**拒绝执行任何写库断言**，并明确记一条失败（不静默跳过）。这条同时证明"没碰真实库"与"不会调模型"。
4. **防假通过**：正向断言（会话出现在所属课程下）失败时，后续"切到不存在课程就消失"这类**恒真**断言**记为失败**，并写明"前置未过，本断言无信息量"。
5. **课程 id 从界面读取**，不再硬编码 `1`（用户真实库里根本没有 id=1 的课程）。
6. **类名歧义在产品侧修掉**：新增的课程上下文栏改用 `.chat-scope-bar`（不再与 `.session-bar` 共用），并加断言"两个栏各恰好 1 个"。
7. 失败时把测试库复制到 `%TEMP%` 供排查，**不留在用户的数据目录**里。

### 2.5 闸门脚本自己被 BOM 问题打挂

用编辑工具改完 `scripts/verify-m0.ps1` 后，文件的 UTF-8 BOM 被剥掉，PowerShell 5.1 按 GBK 读 → 满屏乱码 parse error，**闸门连第 1 步都跑不到**。

**教训**：项目第 6 步专门查 BOM，但它**救不了闸门脚本自己** —— 脚本解析不过，第 6 步根本不会执行。已补回 BOM 并在 README 的快速开始里写明这条工作规则。

### 3.1 契约 §四要求的"端到端真机证据"（这是本轮的重点验收）

`scripts/smoke-desktop-ui.mjs` 在**真 WebView2 + 真 Tauri IPC + 真 SQLite** 上跑出 **15/15**，其中关键三条：

```
[PASS] 隔离自检：空库无 Key ⇒ 演示模式（既没碰真实库，也不会调模型）
[PASS] 重载后该会话出现在课程 1 的会话列表里（course_id 真的落库了）
[PASS] 切到不存在的课程（100001）后该会话消失（证明按课程过滤真的生效）
```

- 第一条：**先证明环境是隔离的**，否则后面任何"通过"都不可信。
- 第二条：提问 → 落库 → **整页重载**（= 从 SQLite 真读一次）→ 会话仍在该课程下 ⇒ `course_id` 确实写进了库，且列表按课程过滤真的生效。
- 第三条：**负向对照**。只看正向断言时，一个"永远返回全部会话"的假实现也能骗过（我本轮就被这条精确骗过一次，见 §2.4 第 4 点）。

## 五、M4 + R1 的诚实边界（对外口径务必一致）

- **归属是用户的显式选择**，界面始终可见当前课程上下文；`/assistant` 无参数**就是不限定课程**，最近使用的课程只做**可选提示条**，**绝不自动改变检索范围**。
- **检索范围与界面文案同源**（同一个 `effectiveScope`）：写全库就按全库查，写某课就只搜该课。
- **提炼出的先验知识不自动入库**：必须生成 → 预览（可勾选可编辑）→ 点确认才写库；一律标 `source='ai'` + `source_ref='从对话提炼 · 待核对'` + `confidence=0.4`（低置信、`verified=0`）。
- **素材含 AI 自己的回答**，故提示词**逐字声明**「【春晓】的回答也是 AI 生成的、未经核实，不得当作事实依据」，并要求**禁止编造**、存疑处显式标注。
- **截断如实告知**（用了多少条、是否截断）；**无记录不生成**（不用模板冒充）。
- 掌握度仍是**本机统计**：每条并列样本数（`evidence`），`attempts < 3` 走灰态「样本不足」、**不给数字、不进弱项榜**；文案一律「本机统计」，**不是强化学习**。
- **未配 Key 一律走演示模式**（不调模型、不给假结果）。
