### 一条必须先说清的现实约束（决定了第 1 件事怎么做）

**「无视觉模型时自动转录兜底」在纯本机条件下不成立**：项目明确「不做本地 OCR」，
`lib/vision.ts` 的"转录"本身就是**把图片发给能看图的模型**。因此：

- 若主模型**能看图** → 直接把图发过去（最准）；
- 若主模型**不能看图**、但用户**另外配了视觉模型** → 先用视觉模型把图转成文字，
  再把文字发给主模型（并在消息里如实标注「图片已转成文字」）；
- 两者都没有 → **明确报错并给出可操作建议**，绝不假装看懂了图。

这就是本轮的图片路线（`ai` 主模型 + `ai.vision_*` 可选视觉模型）。

## 一、数据模型

### 1.1 `chat_messages.images`（新增列，走 `ensure_column` 幂等迁移，零破坏性 DDL）

```
ALTER TABLE chat_messages ADD COLUMN images TEXT   -- JSON 数组，元素是完整 dataURL
```

- 元素形状：`"data:image/jpeg;base64,<b64>"`（前端可直接塞 `<img src>`）。
- 旧库/旧消息该列为 `NULL` → 前端按「无图片」处理（**不把 NULL 当空数组以外的东西**）。
- **大小双保险**：
  - 前端落库前统一压缩（最长边 ≤ 1600px，JPEG q≈0.82），单条消息图片总量 > 3 MB 时提示并拒绝；
  - Rust `chat_history_save` 侧硬上限 **6 MB**（超出返回可读中文错误），保护数据库不被单条消息撑爆。

### 1.2 新增 settings 键

| 键 | 含义 |
| --- | --- |
| `ai.vision_base_url` / `ai.vision_api_key`（加密，与 `ai.api_key` 同机制）/ `ai.vision_model` | **可选的独立视觉模型**。三项全空 = 用主模型 |
| `ball.course_id` | 悬浮球当前选中的课程（**主程序持有**，单一事实来源；空 = 不限定课程） |

> 口径：`ball.course_id` **不自动套用"最近课程"**（严守 `docs/11` §一 第 3 条）；
> 默认 `NULL` = 不限定课程，由用户在球面板显式选择。

## 二、图片提问的接口口径（前端 ↔ 模型）

- 传输层**无需改动**：`lib/ai.ts` 的 `ApiContentPart` 早已支持 `image_url`。
- 需要改的是**消息装配**：当前 `useChat.send` 把历史一律映射成 `{role, content: string}`。
  本轮改为：**只有本轮这条用户消息**带图片（`content: [{type:"text"},{type:"image_url"}...]`），
  历史消息仍走纯文本 —— 避免多轮图片把上下文与费用顶爆。
- 图片在界面上**随消息气泡一起显示**（可回看），点击可放大。

## 三、悬浮球桥接载荷（**改冻结接口**，逐条登记）

### 3.1 主程序 → 球（`to-ball.json`，随 `show` / `prefill` 下发）

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `courses` | `[{id:number, name:string}]` | 课程列表（供球面板下拉选择）；**空数组合法** |
| `courseId` | `number \| null` | 当前选中的课程（来自 `settings.ball.course_id`） |
| `courseName` | `string \| null` | ★ 新增：课程名（球侧直接显示，不必自己查表） |

> `courses` / `courseId` 是 `docs/11` §六 **已冻结**的形状；`courseName` 为**本轮新增**，在此登记。

### 3.2 球 → 主程序（`from-ball.json`）

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `course_id` | `number \| null` | ★ `docs/11` §六 已冻结：球回推时带上它 |
| `answer` | `string \| null` | ★ 新增：球侧已生成的回答（供主程序落库） |
| `images` | `string[] \| null` | ★ 新增：本轮图片的 dataURL（供主程序落库） |

新增 `action`：

| action | 语义 | 主程序动作 |
| --- | --- | --- |
| `set_course` | 球面板切换了课程 | 持久化到 `settings.ball.course_id`，**不落任何消息** |
| `ask` | 球完成了一次问答 | **直接写库**（见 §3.3），并 emit `ball-push` 供界面刷新 |
| `material_search` | 关联课程材料（**保持原义**） | 按 `course_id` 过滤检索（**这是本轮的行为变更**：原实现写死全库） |

### 3.3 `ask` 的落库口径（关闭 `docs/11` §六 的 G4）

`ball.rs` 直接写库，**不依赖任何页面是否打开**（比"前端挂 `onBallPush`"更稳）：

1. 按 `course_id` 找该课程**最近一个会话**；没有则新建（标题 `悬浮球问答`，归属该课程）；
2. 追加一条 `user`（`content` = 问题，`images` = 图片）与一条 `assistant`（`content` = 回答，`source_kind='ball_ask'`）；
3. emit `ball-push` `{action:"ask", course_id, session_id}` → 前端收到后**刷新会话/消息**（若正看着该课程）。

> 明确不做：不把球侧回答伪装成"主程序检索到材料"的回答；`source_kind` 固定 `ball_ask` 可溯源。

### 过程中踩到并修掉的 5 个真问题（都不是"想不到"，而是"不问就不对"）

1. **面板 CSP 会拦掉图片**：`panel.html` 的 `default-src 'self'` 之下 `data:` 图片会被判为坏图 —— 补 `img-src 'self' data:`。
   **不补的话：缩略图永远显示不出来，而控制台之外没有任何提示。**
2. **`BridgeMsg.text` 必填会让 `set_course` 被静默丢弃**：`set_course` 不带文本，反序列化失败后轮询线程只 `continue` —— 现象是"球说已切换、主程序毫无反应"。已改为可选并加单测锁住。
3. **`chat_history_save` 是"先删后插"整表重写**：图片若在事务中途才判超限，会留下半截消息。改为**先整体校验再进事务**。
4. **桌面真机冒烟跑的是旧 exe**：改了 Rust 却只跑 `cargo check` 时，`target/debug/*.exe` 仍是旧二进制 → `images` 全为 null、超限不报错，**看起来像功能没实现**。必须先 `cargo build`。
5. **自检不该改变被测对象的状态**：第一版把"图片落库自检"的会话留在库里，污染了后面 R1 的「会话列表」断言（连带三条失败）。自检会话用完即删。

> 另记一处**已知边界**：答疑页的消息气泡目前是**纯文本渲染**（`Assistant.tsx` 直接渲染 `m.content`），
> 模型返回的 Markdown 语法会原样显示。这是 R4 之前就存在的问题、不在本轮范围，但**图片消息不受影响**（图片单独渲染）。
