## 一句话定位

把一门课从"开学"到"考试"的全过程放进一个本地应用：**建课 → AI 建知识骨架 → 导入课件/电子书 → 划词或拍屏提问 → 一键生成笔记 → 按弱项刷题 → 看着掌握度涨**；桌宠与番茄钟在旁边陪着。

**适用场景**：课后理解、复习、笔记整理、答疑自测。
**明确不面向**：考试场景（见 `docs/00-可行性评估.md` §7.1）。

## 三条必须先读的结论

1. **复用率很高**：14 项预想功能中 **7 项照搬、4 项小改、3 项是新活**。悬浮球（自动读取 / 手动抓取 / 拖动 / 气泡 / 换肤）整套约 50 KB JS 可直接复制。
2. **「自我迭代」不能乱说**：客户端做不到训练模型，只能加权题库与提示词。产品内必须区分「真实实现」与「协议仿真」，并写明"这不是强化学习"。（评估文档 §7.2）
3. **鲸鱼娘素材不能直接搬**：`maid-whale-webui` 虽为 BSD-3-Clause，但其 `NOTICE` 已声明不为所描绘的第三方美术/名称/商标授权，且角色源自第三方 sprite sheet。**桌宠形象走原创**，只借鉴其 `pet.json` 的数据模型。（评估文档 §4.3）

## 快速开始

以下命令均在 **Windows / PowerShell** 下执行（含中文的 `.ps1` 必须带 UTF-8 BOM，否则会被按 GBK 误读 —— 见 [`docs/02`](docs/02-M0实现记录.md) §3.3，质量闸门第 6 步已自动拦截）。
> ⚠ **但闸门脚本自己缺 BOM 时，它会直接解析失败、连第 6 步都跑不到**（本轮真实踩过）。用编辑工具改过任何 `.ps1` 之后，**务必立刻复检 BOM**。见 [`docs/12`](docs/12-M4收口与R1实现记录.md) §2.5。

```powershell
# 1. 前端依赖
npm install

# 2. 悬浮球依赖（Electron）
#    ⚠ 本机访问 GitHub releases 受限，Electron postinstall 会 ECONNRESET。
#    若母本 floating-ball/node_modules 可用，直接本地复制最快：
#    robocopy <母本>\floating-ball\node_modules floating-ball\node_modules /E
#    否则走镜像：$env:ELECTRON_MIRROR="https://npmmirror.com/mirrors/electron/"
cd floating-ball; npm install; cd ..

# 3. 生成品牌图标（换形象后跑一次；悬浮球打包品牌化依赖 floating-ball/assets/icon.ico）
#    从 src/assets/mascot.svg **唯一母版**产出：5 档 PNG + ICO(7 条目) + 悬浮球 png/ico + 前端 favicon
#    ⚠ 需要本机有 Edge（用无头 Edge + CDP 光栅化，零第三方依赖）；
#      没装 Edge 时脚本会明确报错并**保留既有图标产物**，不会留下坏图标
powershell -File scripts/make-icons.ps1

# 4. 质量闸门（9 步：tsc / vite build / cargo check / 图标回读 / 品牌残留 / 脚本编码 / 浏览器层 UI 冒烟 / 桌面真机 UI 冒烟 / 悬浮球面板版面守门）
powershell -File scripts/verify-m0.ps1
#    想跳过第 7、8、9 步（UI 层）：-SkipUI      只想快验前端：-SkipCargo

# 5. 桌面版开发（已实测：vite HTTP 200 + 主程序进程存活）
npm run tauri dev
#    也可只编译再直接跑 exe：cd src-tauri; cargo build; .\target\debug\chunxiao-study.exe

# 6. 前端 + 悬浮球一键联调（只调前端时用 npm run dev）
npm run dev:all

# 7. 冒烟测试（六个都可复跑；脚本自带清理与还原，不会破坏本机数据/浏览器）
powershell -File scripts/smoke-desktop.ps1        # 桌面端到端 8 项
powershell -File scripts/smoke-ball-bridge.ps1    # 反向桥接 + BYOK 配置同步 + R5/R5.1 新断言 17 项
powershell -File scripts/smoke-material-chain.ps1 # 材料检索桥接闭环 11 项（两轮）
powershell -File scripts/smoke-ball-panel.ps1     # 悬浮球**面板版面守门** 50 项（无头 Edge + CDP 渲染 panel.html 本身；
                                                  #   断言关键控件完整落在窗口内 / 互不重叠 / 带标签与文字，
                                                  #   R11 起**连设置抽屉一起测**：每行在窗口内、行间不重叠、不压到内容框）
powershell -File scripts/smoke-ui.ps1             # 浏览器层 UI 124 项（无头 Edge + CDP，含诚实红线边界、计时器行为、折叠区守门、课程跟随与按天分组、全站工程口径扫描、
                                                  #   R12：建课后课程选择器无需刷新即更新 + 笔记沉浸式编辑页/公式/图片）
powershell -File scripts/smoke-desktop-ui.ps1     # 桌面真机 UI 18 项（WebView2 + CDP，真 Rust IPC + 真 SQLite；
                                                  #   自动移开并还原你的数据库，且要求主程序未在运行）

# 8. 打包悬浮球（产出便携版 + win-unpacked，供主程序安装包内嵌）
#    ⚠ **换过图标/形象后必须重打这一步**：win-unpacked 是**构建产物**，里面嵌的是
#      "构建当时"的图标 —— 只跑 make-icons.ps1 不会更新它。重打后按版本口径递增
#      悬浮球版本号（floating-ball/package.json），否则旧常驻进程会顶掉新包。
cd floating-ball; npm run dist; cd ..
#    → floating-ball/dist/春晓助手 1.0.8.exe 与 floating-ball/dist/win-unpacked/

# 9. 打主程序安装包（NSIS，内嵌悬浮球与版本化资源目录）
#    ⚠ 打包前必须先跑满第 4 步的闸门（项目规则：质量检查未过禁止打包）
#    ⚠ **出 exe 前先关掉正在运行的春晓**：否则 cargo 覆盖 target\release\chunxiao-study.exe
#      会报 `failed to remove ... (os error 5 拒绝访问)`（R9 踩过）。第 8 步同理。
npm run tauri build
#    → src-tauri/target/release/bundle/nsis/春晓_0.8.0_x64-setup.exe（已实测，见下）

# 9'. 只出 release exe、**不打安装包**（迭代更快；R7 起用过，R10 又恢复走完整包）
#     ⚠ 它是**未打包**的裸 exe，不带安装/卸载/开始菜单项，也不会内嵌悬浮球资源目录；
#        要完整交付仍然走上面的第 8 + 第 9 步。
npm run tauri build -- --no-bundle
#    → src-tauri/target/release/chunxiao-study.exe
```

> **步骤 9 需要先做步骤 8**：`bundle.resources` 指向 `floating-ball/dist/win-unpacked`，该目录不存在时打包会失败。
> ⚠ **改了悬浮球源码就必须重跑步骤 8**：安装包内嵌的是 `floating-ball/dist/win-unpacked` 这个**构建产物**，
> 只改 `floating-ball/src` 不会自动更新它（R4 删翻译、R5 重排面板、R5.1 重做两个框都是这样：**必须重打**）。
> **R10 就照这条走的**：本轮改了悬浮球的皮肤/面板/换肤窗配色 → **先重打 1.0.8，再打 0.8.0 安装包**。
> （对照：R7 当时按用户要求「先打 exe」，于是**没**重打悬浮球，0.7.3 因此只有裸 exe。）
> ⚠ 步骤 9'（`--no-bundle`）**不走** `bundle.resources`，所以它不会因为悬浮球没重打而失败或塞进旧包。
> **安装包已验证到什么程度（0.8.0 实测）**：见本文件末尾「本轮实测」。
> **安装后的实际目录布局**：已由 0.4.0 的**真实安装**证实（安装到 `%LOCALAPPDATA%\春晓\`，含 `win-unpacked-<版本>\春晓助手.exe`、`uninstall.exe` 与注册表卸载项）；**0.6.x / 0.7.x / 0.8.0 尚未真装一次**。
> （注：NSIS 用 LZMA 整体压缩，按字节扫描安装包找路径/文件名会 **0 命中**，所以"扫不到"不等于"没打进去"。）
>
> **交付物归集**：`发布包/`（**0.9.0 安装包** + 0.8.1 / 0.8.0 / 0.7.2 / 0.6.1 / 0.6.0 / 0.5.0 / 0.4.0 / 0.3.0 安装包[回退用] + 悬浮球 **1.0.9 / 1.0.8 / 1.0.7** 便携版 + `说明.md`，含 SHA256 与"已验证到哪一步"）。
> **0.9.0 的悬浮球未重打**：本轮 `floating-ball/src` **一个字未改**，`bundle.resources` 现指向
> `win-unpacked-0.9.0`（目录名随版本递增），其内容仍是 **1.0.9**。
